# OOPTDD v3.0 — ouroboros closure

2026-08-05. Base: `5a31112` (post-`055f0a5` "harden(ooptdd): receipt signing,
xlocks, audit policy, repair tooling").

## The question

Does it matter that ooptdd verifies itself? The chain's tamper-evidence is
drilled by `fire_drill`, whose verdict is recorded in the chain; the oracle's
quality is measured by `mutate`, which is run by the harness the oracle
belongs to; the auditor policy forbids self-audit and is enforced by the same
process it governs.

The answer is no — bootstrapping is unavoidable and every verification system
has it. A compiler cannot be fully checked by itself either. The question that
discriminates is different:

> Is there at least one link in the loop fixed by something outside the loop,
> **and is it mandatory?**

ooptdd had three such links. All three were optional.

| link | outside-ness | status before v3.0 |
|---|---|---|
| physical mutation (`fire_drill`, `mutate`) | faults generated by machine, not imagined by author | drill used 2 hand-picked faults |
| cross-machine anchor (LakatoTree) | another machine's memory | separate CLI, no exit code depended on it |
| a different auditor (R1) | another party | degrades to `unverifiable`, chains anyway |

A green receipt could therefore be produced having consulted nothing outside
the process that authored it. That is the failure — not the self-reference.

This is not a hypothetical. The same shape has already been measured in this
codebase's neighbours: the capture harness's `false-green` (2026-07-17
deployment verification was decorative), and the 2026-07-28 chain incident,
where the repair mechanism itself was introduced under a misdiagnosis that was
later withdrawn.

## What was found

Machine-generating the attacks instead of choosing them (`ooptdd/attacks.py`,
16 attacks) produced three findings the two hand-picked faults could not.

### F1 — tail truncation is undetectable locally

`verify()` walks `seq`, `prev_hash`, `hash`. Dropping the **last** record
leaves a perfectly consistent prefix. Run a receipt, dislike the verdict,
delete the line, re-run: `append()` re-verifies happily and continues the
chain. Nothing in the file could ever object, because the file does not know
how long it has been.

Same class: `full_rewrite` and `rewrite_middle` — an attacker who recomputes
the tail's hashes produces an internally flawless chain.

Closure: `verify(expect_head=…, expect_min_len=…)` takes the facts from
outside, and `fire_drill anchor-check` now compares local `seq` against the
**anchored high-water mark**. A local head below it means records were removed
after being anchored. This is the truncation detector, and it only exists
because the anchor exists.

### F2 — the repairs skiplist was an unauthenticated override of `verify()`

v2.8 added `<log>.repairs.json` so a documented incident would not make the
chain permanently unverifiable. Good idea; the implementation accepted any
entry with three non-empty strings. Anyone able to write that sibling file
could suppress a hash mismatch on any record by naming its stored hash, with
an `attested_by` field nobody checked.

The live file proves the point: its `seq=25` entry carries a **43-character**
`stored_hash`. It has been there since 2026-07-28 and nothing ever looked at
it, because nothing ever looked at any of them.

Closure: entries are graded `signed` / `untrusted` / `unsigned` / `invalid`
from an ed25519 signature over the entry body checked against the auditor
registry — the crypto v2.9 already shipped, applied to the one file that was
exempt from it. Default rules still honour historical unsigned entries
(backward compatibility), `--strict-repairs` honours only signed ones, and
**the gate always uses strict**. Malformed entries are graded `invalid` and
suppress nothing — but they no longer raise, because one bad line in an
advisory sidecar making every receipt in the repo unverifiable is an
availability hole wearing strictness as a costume.

### F3 — a signature could be stripped or grafted without moving any digest

`record_hash` excludes `signature` so the signature can sign the digest.
Correct, and it also made removal free: strip the block and the hash is
unchanged, `verify()` is quiet, and the anchored head still matches. A signed
audit silently becomes an unsigned one. Grafting a valid signature from
another record was likewise invisible, since `verify()` never checked
signatures at all.

Closure, two parts:
- any `signature` present must verify against **that record's** hash (closes
  grafting, retroactively, for every record);
- signed records now carry `signer_pubkey` **inside** the hashed body, so a
  strip leaves a record still claiming a signer it no longer has.

The retroactive half does not exist. Records signed under v2.9 have no
commitment to their own signer, so stripping their signature is invisible to
the verifier *and* to the anchor. `ooptdd/attacks.py` classifies this as
`legacy_blind` and the census counts the exposure (**4 records**). Re-signing
is the only remedy; pretending otherwise would be exactly the vacuity this
work is about.

## What was built

| module | what it does |
|---|---|
| `ooptdd/attacks.py` | 16 machine-generated tamper attacks, each declaring a detectability class. Inapplicable attacks report SKIPPED with a reason — never a silent pass. `battery_fingerprint()` pins which battery a receipt survived. |
| `ooptdd/fire_drill.py` | runs the whole battery against declared expectations. A `local` miss fails the drill; `anchor_only` and `legacy_blind` misses are reported loudly as the shape of the remaining hole. `anchor-check` gains the truncation detector. |
| `ooptdd/census.py` | counts every progressive-enforcement label on every dimension. Ratchets on regression rather than imposing an invented target. |
| `ooptdd/gate.py` | the single DONE decision. Fail-closed on the outside world: an unreachable tree is `UNVERIFIABLE`, and `UNVERIFIABLE` is not a pass. |
| `ooptdd/run_receipt.py` | `--require-anchor` (exit 3), and the anchoring attempt is itself chained as `kind="anchor"` so "was this ever anchored?" is answerable from the chain. |

Four detectability classes, and the classes are the finding:

- **local** — `verify()` must catch it unaided. A miss means the chain is
  decorative for that fault class. 10 attacks.
- **local_strict** — caught only with `--strict-repairs`. 2 attacks. These are
  what the v2.8 skiplist could whitewash.
- **anchor_only** — `verify()` provably cannot catch it; the information is not
  in the file. 3 attacks. This is why the gate requires an anchor.
- **legacy_blind** — no verifier and no anchor catches it; only re-signing
  retires it. 1 attack.

## Design notes

**Ratchet, not target.** The census could have shipped with coverage floors.
It ships with `--ratchet` instead: coverage may not decrease versus a previous
census. A floor is a number to optimise toward and then stop; forbidding
regression forbids only the actual failure mode. Explicit floors remain
available via `--min-coverage` for dimensions where a floor is a real policy
decision rather than a guess.

**An empty dimension has coverage `None`, not `1.0`.** Otherwise a chain with
nothing in it reads as perfect, and `--min-coverage` could be met vacuously.
Tested (`test_empty_dimension_is_not_full_coverage`, `test_floor_cannot_be_met_vacuously`).

**UNVERIFIABLE is a gate failure.** "I could not check with the outside" and
"the outside agreed" must not share an exit code. `--allow-unanchored` shows
the other conditions with the tree down and can never return 0.

**No historical record was invalidated.** `signer_pubkey` is a new field on new
records; every one of the 76 existing records still hash-verifies
(`test_signer_pubkey_does_not_disturb_legacy_hashes`), and the chain verifies
clean under both default and strict rules.

## What is still open

1. **4 legacy-signed records remain strip-blind.** Not closable by
   verification. Re-sign under v3.0 to retire; the census reports the count
   until then.
2. **The repairs skiplist is still honoured unsigned by default.** Strict mode
   and the gate refuse it, but `verify()`'s default rules do not. Sign the
   four historical entries (or withdraw the file — its own note says the
   entries are no-ops against a clean chain) and the default can be tightened.
3. **The anchor's own integrity is out of scope here.** The gate trusts what
   LakatoTree returns. That is a different trust domain with its own audit
   history, which is the point of using it — but it is an assumption, not a
   proof.
4. **`mutate.py`'s operator set is still authored.** The battery fixed the
   chain's negative oracles; the mutation operators for receipts themselves
   (comparison flips, arithmetic swaps, one domain mutant) are still a
   hand-picked list. Same critique, different target.

```bash
python -m ooptdd.fire_drill drill --strict-repairs --json receipts/drill_battery_20260805.json
python -m ooptdd.census --json receipts/census_20260805.json
python -m ooptdd.gate receipt_cosine_floor --ratchet receipts/census_20260805.json
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest tests/test_ouroboros.py -q   # 27 passed
```
