## Role and claim boundary

This is `B2_EXPEL_INSPIRED_TEXT_LESSON`, an external text-state secondary
comparator. It creates no HSWM canonical atom, owner decision, credit, Permit,
or revision and makes no direct ExpeL runtime-parity claim. D-3's primary G1
remove/restore, sham, shuffled-credit, and compiled-mediation estimand is
unchanged. G0 remains `NOT_PASSED`; G1 is `NOT_EVALUATED`; no efficacy or
canonical HSWM admission follows from this occurrence.

## Fixed sequence

1. Rank groups before games using the new B2 occurrence/protocol identity and
   exact pool/locator hashes. Select 8 train groups, then 4 `valid_seen` groups
   excluding the selected train groups. Do not decode or select
   `valid_unseen` record details. This is descriptive `valid_seen`, with no
   final held-out population estimate.
2. Run the 8 training episodes with an empty lesson and only episode-local
   observations/actions. At each successful terminal, verify the worker's
   receipt, all action/observation digest joins, and clean process exit before
   requesting one reflection. A failed terminal produces no rule.
3. Store at most one printable-ASCII rule per successful terminal, deduplicate
   exact bytes in training order, and freeze the lesson before evaluation.
   All 4 evaluation episodes receive the same frozen lesson. Evaluation
   outcomes cannot update it. There are no retrieval or few-shot channels.
4. Preserve the entire private prefix, including request reservations before
   POST, observed responses/usage, terminal seals, reflection inputs, and
   errors. Do not retry, replace, refill, or repair an action manually.

The request caps are 240 action plus 8 reflection requests **for each** of
tokenization and completion: 248 + 248 HTTP POSTs overall. Actions allow 64
output tokens; reflections allow 128. A request's fixed timeout must fit the
remaining 36,000-second sequence deadline. The rendered lesson is capped at
5,120 UTF-8 bytes; there is no separate lesson-only tokenizer call. Every full
chat request receives the pinned tokenizer's context preflight. Missing usage
is recorded as unknown, not zero. Reflection cost is separate from action
cost; this is not a budget-matched B0 effect estimate.

## Runtime and custody

Reuse the exact checked-in ALFWorld PDDL-only ARM64 qualification, source
archive, dependencies, model snapshot, vLLM image digest, and GB10 identity.
The B2 lease launches a fresh container with the qualified controls and fresh
cache directories, then compares its generation-success counter with issued
completion requests. The existing shared model service is not reused.

The worker has no network namespace access; the model endpoint has host
loopback ingress. Independent container egress isolation is not claimed.
Private selections, task files, traces, outcomes, and lessons stay outside the
repository. Custody remains within a trusted maintainer domain with sudo;
neither privilege independence nor a second party is established.

## Execution and interpretation

The selection entrypoint is `python -m hswm.experiments.expel_b2_selection`
with `--protocol`, `--pool`, and `--locator`, through `hswm-run`. It writes
private/public selection receipts only into that wrapper's output directory.
The live entrypoint is `python -m hswm.experiments.expel_b2_live`; all paths
are explicit and it consumes the previously sealed selection.

Success rates are available only after the full sequence and final service
attestation complete. An incomplete terminal preserves valid observed counts
but emits no success rate. An inner complete sequence is insufficient when
the enclosing host attestation fails. Public receipts contain aggregate
counts and hashes, never task identities, prompts, actions, or raw rules.
