# Semantic repair v2: 요약 형식 개선, 판단 후보 미채택

2026-11-15 · agent(codex) / SECONDARY_AI · 독자: 다음 native 판단 프로그램을 설계하는 연구자와 인역강 연구 조회.

## 결과와 결정

**v2의 native 실행·원시 기록 감사는 완료했고, 개발 gate는 실패했다.** 후보를 기본 프로그램으로 채택하지 않았다. **미노출 18문항은 열지 않았다.**

| 이번 개발 20쌍 | 기준선 | v2 후보 |
|---|---:|---:|
| 라벨 정답 | 16/20 | 15/20 |
| 라벨과 참조 근거 모두 일치 | 14/20 | 15/20 |
| 작성 경계 사례 | 7/8 | 8/8 |
| 정보 부족 라벨 정답 수 | 6 | 7 |
| 입력 tokens | 94,866 | 110,127 |
| 출력 tokens | 2,014 | 1,655 |
| 전체 tokens | 96,880 | 111,782 |
| completion 호출 | 40 | 40 |

근거 포함 paired 결과는 3개 개선·2개 회귀·15개 동률이다. 라벨은 2개 개선·3개 회귀다.
사전 조건 중 근거 순증 ≥2에 못 미친 +1, 라벨 순증 ≥1에 못 미친 −1, 라벨 회귀 ≤1을 넘는 3개 때문에 실패했다. 경계 ≥7/8 조건은 충족했다. 원래 점수·참조·통과 기준을 바꾸지 않았다.

## 실제 개선된 부분과 한계

첫 분석의 256 UTF-16 unit 한도 포화는 기준선 17/20에서 후보 0/20으로 줄었다.
평균 길이는 253.25→133.65 units, 후보 최대 길이는 177이었다. 후보 20개 모두 목표 200 미만이었다.
이는 형식·길이의 관측이며 분석 내용의 정확성을 뜻하지 않는다.

출력 tokens는 감소했지만 추가된 입력 프로그램 때문에 전체 tokens는 **15.38% 증가**했다.
인용 인덱스 합은 17→16, 가장 가까운 참조 집합 밖 인덱스 합은 6→6이었다.
이 수치는 의미적 인용 정확도의 독립 평가나 새로운 통과 기준이 아니다.

## 재현성에 관한 별도 진단

v1과 이번 v2의 **기준선** 요청을 사후 비교했다. 첫 단계 20개는 JSON 값이 같았지만,
둘째 단계 20개는 모두 달랐다. 64자리 hex 해시를 진단용으로 마스킹하면 둘째 단계 20개도 같았다.
실제 입력에는 `analysis.traceSha256`와 그 영향을 받는 선택/프레임 해시가 포함된다.
응답 message 내용은 둘째 단계 두 사례에서 달랐다. 이 마스킹은 실제 모델에 보낸 새 처치가 아니다.
해시 변화가 응답 변화를 일으켰다는 인과 증명이나 서버 비결정성의 분리 측정으로 읽지 않는다.

기준선 자체도 v1의 17/20·15/20과 이번 16/20·14/20이 다르므로, v2를 과거 후보 점수에 직접 빼서 개선량이라고 하지 않았다. 이번 같은 실험 안의 쌍을 주 비교로 사용한다. 등록명·fingerprint 일치도 weight checkpoint 인증은 아니다.

## 다음 방향

현재 v2는 승격하지 않는다. 다음 후보는 자유문으로 원 주장을 다시 쓰기보다 원 주장과 원문 구절을 명시적으로 결속하는 출력 계약을 검토한다. 원문에 없는 주장 범위의 삽입, 조건과 관측의 잘못된 결합을 별도 반례로 삼는다.

또한 canonical trace·원문 판본·역할·순서를 보존하면서, 모델이 읽는 표현에서 의미와 무관한 실행 식별자의 영향을 분리해 검사할 필요가 있다. 해시를 무조건 삭제하거나 이번 진단용 마스킹을 검증된 실행 방식으로 적용하지 않는다. 실제 문장/역할/판본이 달라지는 경우와 추적 식별자만 달라지는 경우를 구분한 대조가 먼저다.

이는 후속 설계 방향이며 새로운 v3 실험이나 성능 개선을 이번에 입증한 것이 아니다. 보존된 18문항은 다음 실행 전 노출 목록을 다시 확인한다.
