# HSWM Ragnarok research project

Status: **DESIGN_SEEDED_UNJUDGED**.

## Canonical role

This project studies the failure condition named **LX3 Ragnarok** in the
[USER_PRIMARY canon](../../docs/canon/USER_PRIMARY_HSWM_TOKEN_LEARNING_RAGNAROK_2026-08-14.md):
as models, agents, tools, and contexts become more capable, an ever-growing
static semantic harness can consume more interpretation, exception handling,
review, and protocol work than the task itself. HSWM's target response is not a
better static rulebook. Outcome-bound trajectories must become durable
canonical revisions, relations, transition dispositions, and topology that
change later behavior.

Ragnarok is not a synonym for a failed test, a long repository, weak model
performance, or necessary safety constraints. It is a scaling failure in which
manual semantic coordination and its interpretation burden grow instead of
being displaced by causally validated learning. Constitutional invariants,
authority, consent, rollback, provenance, and bounded safety checks remain
necessary; prescribing ordinary cognition and routing case by case does not.

## Target identity, current evidence, and conceptual delta

| layer | statement |
|---|---|
| target identity | Stronger HSWM capability should reduce the marginal static coordination needed per new causally validated behavior. |
| current evidence | The repository has contracts, traces, ledgers, replay instruments, and narrow experiments, but no checked-in result establishes that learned HSWM behavior has defeated static harness growth. |
| conceptual delta | The canon's warning becomes a falsifiable multimetric research program spanning local cells, coalitions, and HSWM-of-HSWMs instead of a narrative label or one scalar dashboard. |

The closest established scientific bridge is ML systems' hidden technical debt:
configuration, glue code, boundary erosion, entanglement, feedback loops, and
monitoring costs can dominate a model-centered system. That literature motivates
measurement but does not prove LX3 Ragnarok or HSWM's proposed solution.

## Research questions

1. At matched task and compute budgets, does accumulated HSWM learning reduce
   static instruction load, manual exceptions, and repair work on fresh tasks?
2. Does removing or shuffling the learned canonical revision and relation state
   remove the benefit, with restoration recovering it?
3. When model capability increases, does useful task work increase faster than
   harness interpretation work?
4. Do emergent coalitions and hyperedges reduce manual orchestration, or merely
   move the static workflow into a graph?
5. Does the same result survive composition from cells to agents, organizations,
   and bounded HSWM-of-HSWMs?
6. Can evidence and safety boundaries remain effective without becoming an
   expanding personal governance toolchain?

## Hypotheses and falsifiers

### RAG-H1 — learned displacement

After a fixed adaptation budget, an HSWM learned arm will be non-inferior on
fresh-task quality and will require less marginal static coordination than a
strong static-harness arm.

Falsify or narrow it if quality falls outside the preregistered margin, or if the
claimed reduction is explained by more calls, hidden prompts, human edits, or
unmeasured external work.

### RAG-H2 — causal ownership

The reduced burden is caused by admitted outcome-bound HSWM revisions.

Falsify it if remove/shuffle interventions do not remove the gain, snapshot
restoration does not recover it, or the update never changes the next dispatch or
action distribution.

### RAG-H3 — capability scaling

Increasing model capability will lower or hold constant harness burden per valid
task outcome when the HSWM loop is learning, but not when static instructions are
the only adaptation channel.

Falsify it if stronger models consistently spend a larger share of measurable
work interpreting the harness without a corresponding causal-outcome gain.

### RAG-H4 — scale closure

Bounded composition of smaller HSWMs will preserve the same burden-reducing
learning law without a central workflow growing in proportion to coalition
variety.

Falsify it if the apparent composite is only federation, a dashboard, a message
bus, or central orchestration; or if multiscale credit and member lineage cannot
be recovered.

## Measurement vector

No single "Ragnarok score" is authorized yet. A composite would hide trade-offs
and invite metric gaming. Every run must report the vector below with numerator,
denominator, attribution method, and uncertainty.

| ID | quantity | minimum operationalization |
|---|---|---|
| `RAG-M1` | static harness load | versioned bytes and tokenizer-specific tokens that prescribe ordinary routing, decomposition, or exception behavior |
| `RAG-M2` | harness interpretation share | attributable model tokens and wall time spent loading, resolving, or repairing static harness instructions divided by total measured work |
| `RAG-M3` | manual exception rate | human-authored case-specific rules or workflow edits per fresh accepted task family |
| `RAG-M4` | causal learning yield | admitted revisions that pass fixed-context intervention and change held-out behavior per call, token, compute, wall-time, and human-minute budget |
| `RAG-M5` | evidence latency | work from preregistration or direct start to the first valid causal block, not to the first green instrument |
| `RAG-M6` | instrument-failure share | invalid, protocol-failed, or measurement-only runs divided by all attempted research runs |
| `RAG-M7` | scale overhead | coordination work added when moving from components to the bounded composite, normalized by new task/coalition variety |
| `RAG-M8` | invariant effectiveness | unsafe or unauthorized effects caught, false refusals, rollback success, and unmeasured escape rate |

Instruction length alone is not Ragnarok: short instructions may be expensive and
long safety contracts may be necessary. The decisive pattern is rising static
coordination burden without proportional, causally attributable outcome gain.

## Experiment sequence

1. **RAG-E0 — retrospective burden audit.** Reconstruct a time series from
   checked-in commits and DNRD-style run records. Classify causal blocks,
   instrument failures, static rule growth, and time-to-evidence. This is a
   diagnostic baseline, never an efficacy result.
2. **RAG-E1 — matched-budget displacement trial.** Compare a strong static
   harness, direct LLM, text-lesson baseline, and outcome-bound HSWM learned arm
   on fresh task families. Freeze budget accounting and hidden-human-work rules
   before execution.
3. **RAG-E2 — model-capability crossover.** Repeat E1 across at least two model
   capability levels without silently rewriting the harness for the stronger
   model.
4. **RAG-E3 — fractal composition trial.** Compose previously measured HSWM
   units and test coalition formation, multiscale credit, regrouping, and central
   orchestration growth under bounded interventions.

The first runnable work item is `RAG-E0`. It should reuse existing history and
run artifacts directly. Building a new adjudication bureaucracy before the
measurement would reproduce the object under study.
