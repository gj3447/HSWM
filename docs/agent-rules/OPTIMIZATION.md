# HSWM optimization rules

2026-10-07 사용자 요청으로 적용하는 작업환경 규칙이다. 여섯 이름과 세부 공학 문구는
AI의 정리이며, [원문·7군단장 대응](../canon/USER_PRIMARY_HSWM_OPTIMIZATION_RULES_2026-10-07.md)과 구분한다.
`routes.json`이 선택한 섹션을 끝까지 읽는다. 자동 웨이트 학습이나 효능의 증명은 아니다.

## R1 task activation

**작업 조건부 규칙 활성화.** AGENTS.md는 진입점과 선택 기준으로 유지한다. 상세 규칙은
작업·대상 경로에 따라 선택되는 Source 노드에 둔다. 선택한 규칙은 필요한 전제와 함께
끝까지 읽고, 작업 범위가 바뀌면 다시 선택한다. 규칙을 짧게 만들기 위해 적용되는 의무를
누락하거나 잘라 읽지 않는다. 단순 조회에 그래프 설계 규칙 전체를 활성화하지 않는다.

## R2 cli execution

**CLI 중심 실행.** 실행 가능한 작업의 기본 인터페이스는 기존 CLI로 둔다. 작업 노드에서
실제 명령·입출력·실행 조건을 찾을 수 있게 연결한다. 그래프에서 명령을 찾았다는 사실은
실행 권한이 아니다. 이미 지원되는 CLI를 재사용하고, 내용 연결을 위해 새 실행기를 만들지 않는다.

## R3 cli usage binding

**CLI 사용법의 그래프 결속.** 명령의 안정된 식별자에 실제 launcher, 소유한 사용 안내,
적용 하위 명령·인자와 도움말 경로를 연결한다. 처음 쓸 때 설치본 도움말과 선택한 사용법을
대조한다. 위치가 바뀌면 참조 대상의 위치 정보를 수정한다. 관련 없는 사용법을 모두 넣은
노드 대신 [CLI 진입점](CLI.md)에서 해당 작업의 안내로 내려간다.

## R4 context granularity

**컨텍스트에 맞는 노드 분할.** 독립적으로 선택·재사용할 수 있는 의미와 책임을 기준으로
노드를 나눈다. 한 노드가 조합 전에 컨텍스트를 독점하는지 확인한다. 적용 조건·예외·출처가
본문과 분리되어 사라지지 않게 결속한다. 바이트 수 감소나 노드 수 증가만으로 개선을 판정하지 않는다.

## R5 selective connectivity

**선택적·느슨한 연결.** 작업별로 필요한 부분만 조합되도록 연결한다. 공통 조건이나
사용법은 식별 가능한 중간 노드로 모을 수 있다. 중간 노드는 선택·재사용·참조 유지에
기여해야 하며, 전부를 다시 불러오는 허브나 의미 없는 우회 경로가 되어서는 안 된다.
역할·방향·문맥과 필요한 의존성을 보존한다.

## R6 semantic contribution

**의미 기여에 따른 재구성.** 분할·연결·웨이트 변경이 작업 해석·선택·실행에 만드는
차이를 구체적으로 확인한다. 구분이 기여하지 않고 늘 함께 쓰이는 노드는 병합 후보로 검토한다.
병합 뒤에도 출처·역할·예외와 선택 결과를 보존한다. 의미를 바꾸려는 변경은 실제 판단의
변화를, 표현만 정리하는 변경은 의미 보존과 읽기 비용을 확인한다. 과거 원문과 이력을 지우지 않는다.
