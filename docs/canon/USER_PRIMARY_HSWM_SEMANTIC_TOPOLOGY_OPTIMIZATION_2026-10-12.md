# 자동 W 갱신과 의미론적 연결·구조 최적화

기록일: 2026-10-12. 사용자 발화는 `USER_PRIMARY`, 제목·명칭·아래 재서술과 기존 개념의
연결은 `SECONDARY_AI`다. 이번 작업은 요구의 저장이며 실행 그래프의 자동 수정이 아니다.

## 다음 작업에서 이어받을 요구

아래 다섯 항목은 원문을 구분해 정리한 AI 재서술이다. 번호나 명칭을 사용자 직접 발화로
소급하지 않는다.

1. **T1 실제 자동 W 갱신:** HSWM의 최적화는 실제 작동하는 자동 W 갱신을 목표로 한다.
2. **T2 연결의 강화·약화:** 학습에 따라 의미론적 연결이 강해지거나 약해지면서 최적화되어야 한다.
3. **T3 의미 기여가 작은 중복·중첩의 정리:** 의미론적으로 중복·중첩되어 추가 의미가 크지 않은
   연결과 구조를 그대로 늘려서는 안 된다.
4. **T4 의미론적 공간에 맞는 연결:** 연결의 배치와 구성은 의미론적 공간에서 적합하게 최적화되어야 한다.
5. **T5 노드 구조의 적응:** 새 노드·허브 같은 노드를 만들거나 노드를 제거하는 구조 변화도 최적화에 포함한다.

재서술 한 문장: **HSWM의 자동 W 학습은 의미 기여를 기준으로 연결을 강화·약화하고,
중복·중첩을 정리하며, 필요한 노드·허브의 생성과 노드 제거를 통해 의미론적 연결 구조를 최적화한다.**

## 기존 내용과의 관계

이 요구는 [여섯 요소의 E2 문맥 선택·E4 결과 기반 학습](../operations/HSWM_CORE_SELECTION_LEARNING_BRIDGE_2026-10-10.md)과
[R5 선택적 연결·R6 의미 기여에 따른 재구성](USER_PRIMARY_HSWM_OPTIMIZATION_RULES_2026-10-07.md)을
자동 구조 적응의 목표로 연결한다. 연결 대응은 AI 해석이다.

앞선 활성화 정책 학습은 이 목표의 일부 경로다. 기존 후보 중 무엇을 선택하는지에 더해,
관계 강약과 노드·허브의 생성·제거까지 학습 대상으로 보아야 한다는 방향을 보존한다.
2026-10-11의 [정책 적용→다음 문맥 실행 구현 기록](../operations/HSWM_CONTEXT_POLICY_BRIDGE_2026-10-11.md)은
관계 원문을 유지한 후보 선택 변경의 범위를 밝힌다. 그 구현 기록이나 2026-10-10 설계의 과거
바이트를 이번 목표에 맞춰 덮어쓰지 않는다.

다음 사항은 원문에 덧붙인 **AI 해석의 경계·미정 사항**이다.

- 의미 중첩이 있다는 사실만으로 무조건 삭제한다는 규칙은 아니다. 실제로 구분해야 할 조건·역할·예외와
  조합의 의미 기여를 보존할지 판정하는 방법은 별도로 정해야 한다.
- 연결 강약의 표현, 의미론적 공간의 정의·거리, 중복 판정·허브 생성·노드 제거 조건과 평가 방법은
  이번 발화에서 수식이나 알고리즘으로 확정되지 않았다. 임베딩 유사도나 degree를 기준으로 고정하지 않는다.
- ‘그냥 신경망과 달리’는 사용자가 강조한 설계 관점으로 보존한다. 일반 신경망에 의미 표현이나
  구조 적응이 없다는 검증된 비교 명제로 확대하지 않는다.
- 노드 생성·제거는 기존 ‘동일 규모 CHU’의 자원 조건과 함께 해석해야 한다. 동일 규모가 곧
  불변 노드 수라는 뜻은 기존 원문에서도 확정되지 않았다.
- 이번 ‘저장’ 요청으로 운영 노드를 삭제하거나 자동 수정기를 실행하지 않는다. 향후 구현은 기존
  [헌법](HSWM_CONSTITUTION_2026-08-20.md)의 owner·revision·경험 귀속·복원 계약을 이어받는다.

## 표준 그래프 저장과 조회

[출처 결속 그래프](../../ontology/identity/hswm_core/HSWM_SEMANTIC_TOPOLOGY_OPTIMIZATION_2026-10-12.v1.json)는
원문 1개와 AI 재서술 5개를 분리하고, 기존 HSWM·E2·E4·R5·R6의 안정된 ID를 참조한다.
원문·이 문서·질의·연결 대상의 파일 바이트 SHA-256을 결속한다. 기존 native RDF v2와
공통 SHACL profile, SPARQL을 재사용하며 live KG나 실행 중인 canonical state의 변경을 뜻하지 않는다.

관계 계약은 다음과 같다. 모두 저장소의 출처·개념 탐색용이며 실행 권한이나 동일성을 도출하지 않는다.

| predicate / scope | domain → range | cardinality와 의미 |
|---|---|---|
| HAS_SOURCE / USER_UTTERANCE | 기록 root → 사용자 원문 | 정확히 1; 발화 출처 |
| HAS_CONCEPT / RESTATED_REQUIREMENT | 기록 root → AI 재서술 | 정확히 5; 주제별 요구 분리 |
| HAS_SOURCE / RESTATEMENT_SOURCE | AI 재서술 → 사용자 원문 | 각 1; 해석 근거이며 원문과 동일시하지 않음 |
| REFERENCES / EXISTING_CONCEPT | 기록 root 또는 AI 재서술 → 기존 개념 anchor | root 1, 재서술 1..2; 기존 개념과의 AI 대응 |

조회 질문은 ‘자동 W 갱신에 어떤 의미론적 연결·구조 변화가 요구되며, 그 원문과 기존 개념은 무엇인가?’다.
전체 그래프에 DAG를 강제하지 않는다. 이 투영은 요구와 출처만 담으며 학습 이벤트·W 값·실측 성능을 담지 않는다.
수정 시 원문은 보존하고 새 해석 판본을 남긴다. 이번 추가를 되돌릴 때에는 신규 기록과 탐색 링크만 제거한다.

```sh
src/hswm/effect-runtime/bin/hswm-workspace show semantic-topology
src/hswm/effect-runtime/bin/hswm-workspace query semantic-topology requirements
src/hswm/effect-runtime/bin/hswm-workspace validate semantic-topology
src/hswm/effect-runtime/bin/hswm-workspace bindings semantic-topology
```
