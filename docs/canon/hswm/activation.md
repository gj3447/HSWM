# 4–6조: 국소 활성화·분산 탐색·Map

[통합 헌법](../HSWM_CONSTITUTION.md)의 선택 가능한 한 부분이다. 아래의 실행 계약은
`agent(codex) / SECONDARY_AI`이며 사용자 원문의 구체화다.

## 4. 상황에 따른 국소 활성화

국소 활성화는 HSWM의 기본 작동 방향이다. 입력·목표·세계 상태·기억에 따라 필요한
규칙·관계·연산을 선택하고, 출력과 새 관측이 다음 활성 부분을 바꾼다. 활성화되지 않은
관계도 지속 상태에 남아 다른 문맥에서 다시 쓰인다.

근거: [국지 활성화를 지능의 기본 원리로 본 사용자 방향](../USER_PRIMARY_HSWM_LOCAL_ACTIVATION_INTELLIGENCE_2026-10-18.md),
[분산 활성화](../USER_PRIMARY_HSWM_LIKE_DISTRIBUTED_ACTIVATION_2026-09-29.md).
이를 보편 지능의 과학적 정리나 특정 MoE 알고리즘의 채택으로 확대하지 않는다.

발표에서도 직접 명시돼 있다. [2026-10-21 원문 발췌](../sources/HSWM_SEMINAR_LOCAL_ACTIVATION_2026-10-21.json)의
34쪽은 사용법·사용처가 항상 문맥을 점유하지 않는다는 조건을, 36쪽은 MoE와 그래프 기반
국소 활성화를 지능의 근본 원리 중 하나로 본다는 사용자 주장을 담는다. 11쪽 Map과 17쪽
국소 LLM·지속 학습 설명을 함께 읽는다. 구체적인 기법과 충족 여부는
[원문–헌법–검사 대응](../../operations/HSWM_MULTIHOP_ACTIVATION_2026-10-24.md)으로 확인한다.

### 4조의 이유·문제·구현

**해결하려는 문제.** 모든 규칙을 매번 넣으면 무관한 조건이 경쟁하고 필요한 예외를 찾기
어려워진다. 토큰 수만 줄이면 정답에 필요한 조건까지 빠질 수 있다. 선택의 목표는 현재
과제를 해결할 의미를 보존하면서 필요한 부분이 작동하게 하는 것이다. 같은 장비라도
보정 작업과 결함 검사는 활성화할 규칙이 달라야 한다.

**문헌 근거.** Liu 등, *Lost in the Middle* (TACL 2024, DOI 10.1162/tacl_a_00638,
§§2–3)은 당시 모델·과제에서 정보 위치와 문맥 길이에 따른 성능 차이를 측정했다.
문맥 용량과 활용 능력을 구분할 근거이며 모든 최신 모델의 동일한 실패를 단정하지 않는다.
[원문](https://aclanthology.org/2024.tacl-1.9.pdf).
Shazeer 등, *Sparsely-Gated MoE* (ICLR 2017, arXiv:1701.06538v1, §§2·4)는 입력별
일부 expert 선택과 부하 균형을 다룬다. 조건부 계산의 비교 사례이며 HSWM의 규칙 선택과
신경망 내부 expert routing은 학습 신호·표현·비용이 다르다.
[원문](https://arxiv.org/html/1701.06538v1#S2).

**구현 경로.** `prepareSemanticContext`로 후보·필수 관계·판본·예산을 묶고,
`selectContextActivation`으로 후보를 선택한다. `assembleSelectedSemanticContext`는
필수 관계와 선택 묶음의 완전한 역할·예외를 조립한다. 예산 초과를 조건 삭제로 해결하지
않는다. 비선택 관계는 저장 상태에 남긴다. 현재 LinUCB 선택기는 Li 등(WWW 2010),
§3.1·Algorithm 1의 disjoint linear bandit을 참고한다. 관측한 선택의 보상으로 상태를
갱신하는 한 구현이며 고정된 HSWM 정의가 아니다.
[원문](https://www.schapire.net/papers/www10.pdf).

**현재와 후속·확인 사례.** 선택·조립·결과 갱신은 구현돼 있다. 특성은 caller encoder가
제공하며 자연어 상황 해석 자체가 학습됐다는 뜻은 아니다. 같은 후보에서 상황만 바꾸기,
필수 예외 유지, 무관 규칙 추가, 전체 주입·고정 선택과의 비교를 수행한다. 정확도·누락·
비용을 함께 보며 토큰 감소만 성공으로 세지 않는다.

## 5. 여러 곳을 타고 필요한 부분에 도달한다

[이번 사용자 원문](../sources/USER_PRIMARY_HSWM_MULTIHOP_RECONSTRUCTION_2026-10-24.md)이
명시한 것은 여러 연결을 거치는 탐색이다. 단일 전역 색인이 필요한 정답 집합을 한 번에
알려 준다고 가정하지 않는다. 진입점에서 선택한 관계를 따라 다른 지도·하위 그래프·원문으로
이동하고, 거기서 얻은 정보로 다음 이동·보류·복귀를 결정한다. 고정 트리나 고정 깊이는 필요조건이 아니다.

공학적으로 구별할 집합은 다음과 같다. 이 구분은 새 고정 subsystem 정의가 아니다.

| 구분 | 보존할 정보 |
| --- | --- |
| 발견한 후보 | 위치·UID·역할·판본, 아직 읽지 않았다는 상태 |
| 실제 방문·읽기 | 지나간 연결의 방향·상태, 읽은 정확한 출처와 양 |
| 실행 문맥 | 선택 이유, 필요한 역할·조건·예외·원문, 아직 미확인인 것 |
| 지속 수정 | 실행 결과에 결속된 제안·admission·선행/후속 revision |

여러 홉을 방문해도 각 단계에서는 필요한 부분만 연다. 반대로 한 홉이어도 모든 자료를
주입하면 국소성을 달성했다고 볼 수 없다. 원문을 잠깐 참조한 사실과 실행 내내 문맥에
유지한 사실도 구별한다. 순환·재방문을 허용할 때는 판본·이미 읽은 위치·예산·중단 이유를
추적한다. 중간 결과가 필수 조건을 제거하지 않는지 확인한다.

‘딱 필요한 것’은 독립적인 과제 정답·누락 반례로 평가한다. 읽지 않은 곳에 필수 예외가
없다고 단정하지 않는다. 부족하면 추가 탐색하거나 보류하고, 예산 부족을 ‘관계 없음’으로
바꾸지 않는다. 탐색 비용에는 최초 색인 읽기, 홉, 원문 읽기, 문맥 조립, 저장소 복원도 포함한다.

현재 내용 도구: `hswm-workspace navigate/follow/read`. 명시된 판본의 한 연결을 따라가는
기능이며 스스로 경로를 학습하는 라우터는 아니다. native 실행 문맥은 기존
`semantic-context-runtime.ts`, `semantic-context-activation-runtime.ts`에서 조립한다.
내용 탐색 결과를 곧바로 실행 명령이나 학습 credit으로 전환하지 않는다.

native 다단계 실행은 `executeActivationTraversal`에서 현재 지점의 후보를 선택·실행하고
외부 결과를 W에 반영한 뒤 선택된 다음 지점으로 이동한다. 각 지점의 원문·연결도 필수 관계의
참여자로 결속한다. 중복 피드백·낡은 판본·필수 규칙 삭제를 거부하며, AUDIT·unknown은 갱신하지
않는다. 현재 credit은 홉별 외부 결과이며 최종 보상의 인과 분해가 아니다. 저장소 전체 복원은
여전히 국소화되지 않았고, 예제 통과는 모든 자연 과제의 충분성을 뜻하지 않는다.

### 5조의 이유·문제·구현

**해결하려는 문제.** 질문에 다음 탐색 대상의 이름이 처음부터 들어 있지 않을 수 있다.
‘왜 이 부품의 검사가 실패했나’에서 장비 판본을 먼저 찾고, 그 판본의 보정 예외를 찾아야
할 수 있다. 최초 검색의 상위 몇 개만 읽거나 전역 허브를 모두 펼치는 방식은 이 의존성을
놓친다. 막힌 경로에서 복귀할 수 있어야 하며 예산 소진을 답이 없다는 증거로 쓰지 않는다.

**문헌 근거.** Trivedi 등, *IRCoT* (ACL 2023, arXiv:2212.10509v2, §3.1·그림 2)는
이미 얻은 정보로 다음 검색을 바꾸는 반복 검색·추론을 제시한다. 다단계 QA의 근거이며
원문·권한·판본을 보존하는 HSWM graph traversal을 그대로 구현한 것은 아니다.
[원문](https://arxiv.org/html/2212.10509v2#S3).

**구현 경로.** 읽기 탐색은 `workspace-navigation-runtime.ts`의 명시적 route와
`navigate/follow/read`를 사용한다. native 실행은 `semantic-context-traversal-runtime.ts`의
`executeActivationTraversal`을 사용한다. 현재 지점의 후보와 다음 연결을 읽고, 이전
예측·trace를 다음 사건에 연결하며, 홉별 `executeActivationLoop`의 결과로 계속·보류한다.
필수 관계의 연속 보존, 지점 판본 변경, cycle, hop budget을 검사한다. 현재 최대 홉 32는
해당 구현의 한도이며 헌법상의 고정 깊이가 아니다.

**현재와 후속·확인 사례.** 다단계 실행과 홉별 외부 결과 학습은 구현돼 있다. 종단 성과를
각 홉에 인과적으로 배분하는 학습, 자연어에 따른 새 경로 생성, 저장소 복원의 국소화는
별도 문제다. 2·3단계 의존 질문, 잘못된 분기, 순환, 필수 예외가 뒤 단계에 있는 질문을
사용한다. 방문 후보·읽은 원문·최종 유지 문맥·전체 비용을 구분해 비교한다.

### 5조의 보강: 검색 충분성과 외부 획득 시점

[사용자 후속 원문](../sources/USER_PRIMARY_HSWM_INTERNET_NATIVE_2026-10-24.md)은 검색이
부족한지 판단하고 언제 외부에서 가져올지를 명시하라고 요구한다. 검색 결과의 관련성과
현재 과제를 해결할 근거의 충분성은 구분한다. 필수 사실·역할·예외, 대상·판본·시점,
출처 계보와 충돌을 점검하고 부족한 항목을 다음 탐색의 입력으로 삼는다.

- 필요한 원문이 이미 있으면 해당 구간을 읽는다. 알려진 URL의 본문 확보와 새로운
  출처 발견을 위한 검색을 구분한다.
- 최신 상태가 핵심이거나 사용자가 검색·검증을 요청했으면 해당 외부 원천을 확인한다.
  로컬 근거 누락·출처 충돌·실행과 예측의 불일치가 생기면 필요한 원천으로 탐색을 확장한다.
- 근거가 충분한데 추론이 틀렸다면 추론·실행을 진단한다. 사용자만 아는 목적·선호·현장
  관측은 해당 사람에게 묻는다. 검색 횟수를 늘려 다른 종류의 부족함을 감추지 않는다.
- 필수 근거가 충족되면 사용한다. 중복 결과·예산 소진·접근 실패에서는 질문·원천을
  바꾸거나 미확인 범위를 남기고 보류한다. 검색 실패를 사실 부재로 판단하지 않는다.

원천 변경·사람의 정정은 관련 관계를 다시 활성화하는 사건이다. 사용 중 새 주장이 필요해질
때도 충분성을 재판정한다. 연결된 획득 정책은 과제 결과·누락·비용으로 개선할 대상이다.
모델의 자신감이나 검색 순위만으로 충분성을 확정하지 않으며 판정기 자체도 반례로 검사한다.

근거는 [Sufficient Context §3–5](https://arxiv.org/html/2411.06037v3),
[Self-RAG §3](https://arxiv.org/html/2310.11511v1),
[CRAG §4](https://arxiv.org/html/2401.15884v3)다. 실제 선택 조건·중단·캐시·사람의 참여와
현재 구현 경계는 [인터넷 native 획득 계약](../../research/HSWM_INTERNET_NATIVE_EVIDENCE_ACQUISITION_2026-10-24.md)에 둔다.

## 6. Map은 여러 해상도와 원천을 연결한다

축약 의미 지도, 원문, 코드·도구, 관측된 세계를 버전·역할·변환 조건으로 연결한다.
물리 모델, 연결도, 의미 그래프처럼 다른 층을 연결할 때 대상·관측량·변환 손실·적용 범위를
보존한다. 지도는 원천의 위치를 찾는 데 기여해야 하며 원문을 지워 버리는 요약이 되어서는 안 된다.

근거: [여러 층의 Map](../USER_PRIMARY_HSWM_CROSS_LAYER_MAP_2026-09-27.md),
[R1–R6 선택·분할·연결 원칙](../USER_PRIMARY_HSWM_OPTIMIZATION_RULES_2026-10-07.md).
USL은 기존 자원의 의미 연결·표현 위치를 결속하는 경로로 사용한다. 파일 경로나 링크를
알았다는 사실에서 접근·실행 권한이나 관측의 진실성을 도출하지 않는다.

다음 읽기: 관계의 역할은 [3조](state.md#3-관계의-의미와-semantic-weight),
경로·정책의 경험 기반 수정은 [9조](learning.md#9-결과가-다음-활성화와-의미-구조를-바꾼다).

### 6조의 이유·문제·구현

**해결하려는 문제.** 짧은 요약은 원문의 조건을 잃기 쉽고, 원문만 있으면 큰 구조를
찾기 어렵다. 문서 구간·코드·물리 관측을 연결할 때도 ‘같은 말’과 ‘같은 대상’을 혼동할
수 있다. Map은 질문에 맞는 해상도로 진입하고 필요한 근거까지 되돌아갈 수 있어야 한다.

**문헌 근거와 선택.** Sarthi 등, *RAPTOR* (ICLR 2024, arXiv:2401.18059v1, §3)는
서로 다른 요약 수준을 보관하고 층별 또는 전체 층에서 검색한다. 해상도 선택을 참고하지만
그 논문의 embedding·clustering·고정 tree를 HSWM의 필수 구조로 채택하지 않는다.
[원문](https://arxiv.org/html/2401.18059v1#S3).
Sanderson·Ciccarese·Young 편집, W3C *Web Annotation Data Model* (2017-02-23,
§§4.2.4–4.2.5)는 원문 구간의 TextQuoteSelector·TextPositionSelector를 정의하며 위치만
사용하는 참조의 변경 취약성을 설명한다.
[원문](https://www.w3.org/TR/2017/REC-annotation-model-20170223/#selectors).

**구현 경로.** 현재 내용 bundle의 UID·source_path·source_sha256와 명시적 외부 route를
재사용한다. 구간 참조가 필요한 adapter에는 원문 판본·인용 구간·단위(문자/바이트)를 함께
기록한다. 요약은 저자·원문 의존성을 가진 별도 표현으로 두고 원문 변경 시 재검토한다.
센서와 CAD 간 변환은 좌표계·단위·보정 판본·손실을 선언한 연결로 처리한다.

**현재와 후속·확인 사례.** 전체 원문 해시 결속과 원문 복귀는 현재 기능이다. 위 selector의
모든 종류나 물리 변환이 workspace CLI에 구현됐다는 뜻은 아니다. 원문 한 글자 변경,
동일 문장 반복, 요약에서 빠진 예외, 서로 다른 좌표계의 같은 숫자를 넣어 잘못된 대응을
탐지한다. 요약을 제거해도 원문 경로가 남는지 확인한다.

문헌 확인: 2026-10-24. 위 확인 사례는 구현·평가 설계이며 새 성능 실험 결과가 아니다.
