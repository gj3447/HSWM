# 7–9조: 월드모델·실행·학습

[통합 헌법](../HSWM_CONSTITUTION.md)의 선택 가능한 한 부분이다. 사용자 목표와 현재
공학적 실현·검증 범위를 구분한다. 아래 구성은 `SECONDARY_AI`다.

## 7. 세계·자기 상태에서 예측과 관측으로

HSWM의 지속 관계 상태는 세계와 자신의 구성·능력·도구·실패·계보를 함께 표현한다.
국소 연산은 선택한 상태에서 결과를 예측하고 행동을 제안·실행하며, 이후의 관측과 대조한다.
예측된 미래, 관측한 사실, 반사실 분기, 불확실성을 구별한다. 환경 결과를 미리 입력한 뒤
예측에 성공했다고 기록하지 않는다.

Wolfram형이라는 역할은 관계 상태·국소 rewrite·인과 계보에 있다. Wolfram 물리학,
causal invariance나 우주 전체의 재현이 증명됐다는 뜻이 아니다. 원문은
[8월 헌법 5조](../HSWM_CONSTITUTION_2026-08-20.md#5-wolframian-evolving-hypergraph-월드모델),
구현 질문은 [실현 가능한 구조](../../research/HSWM_IMPLEMENTABLE_ARCHITECTURE_2026-09-27.md)를 따른다.

### 7조의 이유·문제·구현

- **이유와 해결할 문제:** 기억한 사실만 검색하는 시스템은 행동 뒤 무엇이 달라질지,
  자기 도구가 어디에서 실패할지 예측하지 못한다. 반대로 예측을 관측처럼 저장하면 자기
  추측이 다시 정답 근거가 되는 순환이 생긴다. 예를 들어 카메라 교정을 바꾸기 전의 예상
  오차, 바꾼 뒤 측정 오차, 아직 실행하지 않은 대안은 서로 다른 상태여야 한다.
- **외부 근거:** Hafner 등의 **DreamerV3** 고정 판본
  [arXiv:2301.04104v2, 2024, Learning algorithm·World model learning](https://arxiv.org/html/2301.04104v2)은
  행동에 따른 상태·보상 등을 예측하는 학습 모델과 상상 궤적의 정책 학습을 연결한다.
  이는 예측–행동–관측 구조의 참고이며, HSWM의 관계 그래프나 자기모델·프랙탈 성질이
  그 논문으로 증명된다는 뜻은 아니다.
- **구현 방법:** 예측에는 예측 시점의 read-set, 행동 조건, 대상 시각·기간, 예상 결과와
  불확실성, 사용 모델 판본을 연결한다. 실제 관측은 별도 사건으로 남기고 당시의 예측과
  대조한다. 자기 능력도 ‘도구가 존재한다’와 ‘이 조건에서 성공했다’를 나누어 저장한다.
  관측 이후의 정보를 이전 예측 입력에 섞지 않고, 반사실 결과는 실행 관측과 다른 역할로 둔다.
- **현재와 확인 방법:** 기존 semantic 실행·outcome 결속은 이 연결의 일부를 제공한다.
  지속 환경 동기화와 장기 예측 효능은 별도 연구 대상이다. 시간 순서가 고정된 미관측
  과제에서 예측 오차·불확실성의 적합성·도구 실패 예측을 확인하고, 관측 누락·환경 변화·
  자기 능력 과대평가를 반례로 사용한다. 예측하지 않은 결과를 사후 설명한 것은 예측 성공이 아니다.

## 8. 의미와 실제 실행을 결속한다

그래프에 저장된 프로그램은 입력·출력, 역할, 적용 조건·예외, 실제 tool/LLM,
오류·중단·복구와 owner를 연결해야 한다. 설명서를 조회한 것과 도구를 실행한 것은 다른 사건이다.
사용법·모델·프로그램 판본과 실제 전달된 문맥을 실행 결과에 연결한다.

현재 구현의 책임 분리는 다음과 같다.

| 경계 | 기존 구현·계약 |
| --- | --- |
| 원자·읽기/쓰기 집합·판본 | `canonical-atom-v2-schema.ts`, `canonical-atom-v2-durable-runtime.ts` |
| 역할 있는 LLM 의미 실행·outcome·수정 제안 | `canonical-atom-v2-llm-semantic-runtime.ts` |
| 선택된 문맥·실제 전송·응답 | `semantic-context-runtime.ts`, `semantic-context-presentation-domain.ts` |
| 정책 초기화·선택·결과 기반 제안 | `semantic-context-activation-runtime.ts` |
| 한 사용의 자동 평가·owner 갱신·readback | `semantic-context-loop-runtime.ts` |
| 방문 지점별 자동 선택·실행·학습·다음 이동 | `semantic-context-traversal-runtime.ts` |
| admission·영속화·재개방 | 기존 owner writer와 durable state journal |

TS/Effect는 버전 관리되는 해석기와 I/O 경계다. 일상 학습은 그래프 프로그램·관계·정책
판본을 바꾸는 것이며 매번 TS 코드를 고치는 것으로 대체하지 않는다. 도구·규칙·실제 개발이
서로 피드백하는 요구는 [기존 tool-harness 계약](../../operations/HSWM_RESEARCH_WORKFLOW.md#tool-harness)을 잇는다.

### 8조의 이유·문제·구현

- **이유와 해결할 문제:** ‘이 도구로 검사한다’는 설명만 있고 실제 입력·출력과 연결이 없으면,
  그럴듯한 답변을 실행 성공으로 오인하거나 다른 판본의 사용법을 현재 도구에 적용한다.
  실행 중단 뒤 재시도할 때도 이미 발생한 외부 효과와 아직 안 된 작업을 구별해야 한다.
- **외부 근거:** Yao 등의 **ReAct**, ICLR 2023,
  [arXiv:2210.03629v3 §2](https://arxiv.org/html/2210.03629v3)은 언어 기반 판단과 환경의
  행동·관측을 교대로 연결한다. HSWM에는 이를 역할·판본·소유권 있는 실행 기록으로
  구체화한다. 내부 사고 전체를 공개하거나 저장해야 한다는 요구로 확대하지 않는다.
- **구현 방법:** 의미 관계가 실제 호출할 tool/LLM과 입력·출력 역할, 단위, 적용 조건,
  예외, owner를 가리키게 한다. 실행은 선택된 문맥과 호출 판본을 고정하고 성공·오류·중단을
  원래 trace에 결속한다. 재시도 가능한 호출과 중복 실행하면 안 되는 외부 효과를 구별한다.
  수정 후보를 만드는 함수와 실제 영속 상태를 바꾸는 admission 경계를 유지한다.
- **현재와 확인 방법:** 위 표의 runtime이 각 경계를 제공하지만 설명서에 이름을 적은 모든
  도구가 자동 결속되는 것은 아니다. 실제 대표 입력으로 입력 단위·출력 역할·실패 전달을
  확인하고, 잘못된 판본·누락된 필수 문맥·timeout·중복 요청을 넣는다. 문서 조회, 호출 시도,
  실행 완료, 영속 반영을 서로 다른 결과로 보고한다.

## 9. 결과가 다음 활성화와 의미 구조를 바꾼다

필요한 연결은 다음과 같다. 정해진 여섯 프로세스를 만들라는 의미가 아니다.

```text
문맥과 선택 판본 → 실제 의미 전이 → 실행에 결속된 관측·실패·비용
→ 의미·관계·활성화 정책 수정 후보 → owner-valid 영속 revision
→ 별도 실행에서 해당 revision을 읽는 다음 선택·예측·행동
```

사용자 요구에는 연결의 강화·약화, 의미 기여가 적은 중복 정리, 의미에 맞는 배치,
노드·허브의 생성·제거가 포함된다. [자동 W·위상 수정 원문](../USER_PRIMARY_HSWM_SEMANTIC_TOPOLOGY_OPTIMIZATION_2026-10-12.md)을
보존한다. scalar 계수만 갱신한 실험을 이 요구 전체의 완성으로 세지 않는다.
국소 활성화 정책 자체도 경험으로 바뀌는 대상이다.

평가는 부모 상태, 같은 관측만 추가한 상태, 의미 수정 상태를 구별한다. 피드백의 작성자와
관측 범위를 남기며, 자기평가를 독립 환경 관측으로 바꾸지 않는다. 같은 피드백의 중복 적용,
낡은 read-set, 동시 수정 충돌, 소유자 변경, restore를 기존 계약에서 검사한다.
근거가 부족한 제안은 거부·보류할 수 있고 정당한 no-op을 가짜 revision으로 꾸미지 않는다.

완료 기준은 [실행→피드백→갱신→다음 사용 계약](../../operations/HSWM_RESEARCH_WORKFLOW.md#consumer-integration-completion)이다.
국소 실험은 [10월 18일 활성화 진단](../../operations/HSWM_LOCAL_ACTIVATION_DIAGNOSIS_2026-10-18.md)에
실제 개선과 제한이 함께 보고돼 있다. 이 헌법 통합 작업이 그 실험을 새로 실행했거나
운영 상태에 적용했다는 뜻은 아니다. 자연 과제의 장기 자기개선과 통합 효능은 별도 검증 대상이다.

[10월 24일 다단계 연결](../../operations/HSWM_MULTIHOP_ACTIVATION_2026-10-24.md)은 새 native
integration과 별도 프로세스의 다음 사용을 검사한다. 연결된 TRAIN 사용은 기존 runtime이
피드백·W 갱신을 처리하므로 매 사용마다 수동 갱신이나 새 학습 실험을 추가하지 않는다.
평가기의 알려지지 않은 결과, AUDIT, 거절·정당한 no-op은 가짜 성공·revision으로 바꾸지 않는다.

### 9조의 이유·문제·구현

- **이유와 해결할 문제:** 사용 기록만 쌓이고 다음 선택이 그대로이면 경험이 행동을 개선하지
  못한다. 반대로 자기 칭찬·중복 피드백·낡은 문맥으로 W를 바꾸면 잘못된 선택을 강화한다.
  선택한 후보의 결과만 관측하는 상황에서는 쓰지 않은 후보의 성과도 곧바로 알 수 없다.
- **외부 근거:** Shinn 등의 **Reflexion**, NeurIPS 2023,
  [arXiv:2303.11366v4 §3·§5](https://arxiv.org/html/2303.11366v4)은 실행 피드백을 언어 기억으로
  바꾸어 다음 시도에 사용한다. 이는 LLM 파라미터나 HSWM의 모든 W가 자동 학습된다는
  증거가 아니다. Dudík·Langford·Li의 **Doubly Robust Policy Evaluation and Learning**,
  ICML 2011, [arXiv:1103.4601v2](https://arxiv.org/abs/1103.4601v2)는 부분적으로 관측되는
  보상으로 다른 정책을 평가할 때 발생하는 편향과 추정 문제를 다룬다.
- **구현 방법:** 연결된 TRAIN 사용에서는 `executeActivationLoop`가 실행 → 평가 → 학습
  후보 → owner admission → 새 판본 readback을 처리한다. 다단계는
  `executeActivationTraversal`이 방문 지점마다 이 연결을 사용한다. 피드백에는 실제 선택,
  정책·문맥 판본, 출처, 관측 범위, 비용을 묶고 중복·낡은 read-set을 거부한다. 반사실 정책
  평가가 필요하면 실제 선택 확률과 후보 범위도 기록해야 하며, 관측되지 않은 행동을
  임의의 보상으로 채우지 않는다. 이 요구가 doubly robust 추정기 구현 완료를 뜻하지는 않는다.
- **현재와 확인 방법:** **연결된 사용의 W 갱신은 이미 자동 경로의 책임이며, 매 사용마다
  수동 갱신이나 별도 학습 실험을 요구하지 않는다.** 일반 채팅·로그 저장만으로 이 경로가
  실행됐다고 추정하지도 않는다. 새로운 학습 연결을 구현·변경할 때는 중복 피드백, 알 수
  없는 보상, AUDIT, 충돌, 재시작 후 다음 사용을 검사한다. 정책 효능을 주장할 때만 비교군과
  미관측 과제의 성과를 추가로 평가한다. 현재의 지점별 피드백을 전체 경로의 인과 기여나
  임의 의미 위상 재편의 완성으로 확대하지 않는다.

문헌 확인일: 2026-10-24. 외부 결과의 HSWM 적용은 `SECONDARY_AI` 설계 해석이며,
이 문서 보강은 새로운 학습 실행·성능 측정·사용자 비준이 아니다.
