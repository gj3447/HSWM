## DNRD-3 conceptual delta

DNRD-3 makes a scientific change as well as closing the observed evidence
path:

1. The measured cause is an outcome-bound routing-disposition revision
   `W0 -> W1`; every heldout route readout is bound to a fresh recovery and is
   recorded before model dispatch.
2. The private scorer's integer outcome depends only on the preregistered
   context-to-correct-route binding and the route already selected. Model text
   cannot change the outcome value or its digest.
3. `RAW_EQUAL_BUDGET` is removed as a scientific arm. Replaying the same eight
   retained update records from W0 is a no-model admission gate that must
   reproduce W1's numeric payload and heldout route readouts.
4. The scientific arms are only `FULL`, exact `NO_MEMORY_ROLLBACK`, and matched
   `BINDING_DERANGED_NUMERIC_PLACEBO`.
5. The live response is a post-route nuisance/provenance channel. Each request
   uses server-constrained strict JSON with both public episode candidate tokens
   in a dynamic enum; the selected token is not the sole permitted value.
6. Production durable-ledger finalization rereads the validated path rather
   than a validator return value; accepted live events carry the same complete
   chat configuration required by consumers; absence of both terminal
   artifacts produces a deterministic conservative `VOID_PROTOCOL` machine
   result rather than an unstructured CLI refusal.

These changes are prerequisites for measuring the causal seam. They are not
the result of that measurement.

The resulting test is a deterministic causal-conformance diagnostic, not a
statistical discovery test: the future seed hides concrete identities and
bindings until after freeze, but the fixed update rule implies the finite
contrast if the implemented transition, recovery, actuation, and binding
semantics are correct. A GO therefore certifies that narrow implemented seam;
it is not evidence that a model discovered or learned the rule.

## Exact falsifiable question

> Given one preregistered sequence of response-independent, scorer-outcome-bound
> revisions of a schema-admitted routing-disposition atom, does W1 persist
> through fresh-process recovery and cause the same repeated contexts to select
> the scorer-predicted route before model dispatch, relative to exact W0
> rollback; and does a matched fixed-point-free permutation of context bindings
> remove that context-specific alignment?

The fixture keeps four future-seeded streams, four contexts per stream, two
routes, and one forced exposure of each context-route cell. Training therefore
has eight calls per stream and 32 total calls. Heldout reuses the same contexts
twice, so this is not unseen-context generalization. Three arms across 32
heldout episodes produce 96 evaluation calls and 128 total generation calls.
There are no retries.

For each stream, the finite GO rule is fixed before the future seed is known:

- `FULL` has positive route reward on exactly 8 of 8 heldout probes;
- W0 has positive route reward on exactly 4 of 8 probes;
- DERANGED has positive route reward on at most 4 of 8 probes;
- FULL's selected route differs from W0 on exactly 4 of 8 probes; and
- FULL's selected route differs from DERANGED on at least 4 of 8 probes.

All four streams must satisfy the rule, and all identity, chronology, recovery,
replay, immutability, leakage, call-accounting, and evidence-closure gates must
also pass. A complete valid occurrence that misses the finite route rule is
`DIAGNOSTIC_NO_GO`. Structural contradiction is `VOID_PROTOCOL`. A bounded
post-dispatch operational failure with a sealed terminal and index is
`INCONCLUSIVE_OCCURRENCE`.

## Intervention and controls

- `FULL` applies eight private route-binding outcomes per stream through the
  fixed signed-integer rule and recovers W1 in fresh bridge processes.
- `NO_MEMORY_ROLLBACK` recovers immutable W0 and measures the same heldout
  contexts.
- `BINDING_DERANGED_NUMERIC_PLACEBO` preserves update multiset, precision,
  L1/L2 norms, and routing-payload byte count while assigning each receiver
  context a nonself donor within the stream.
- The fixed-rule replay gate materializes a separate bridge-owned replay mount
  from W0 using the retained update records, performs no model call, and must
  reproduce the FULL numeric payload and route readouts.

W0 controls preexisting tie-break routing. DERANGED controls global update
magnitude and record count while breaking the context-specific binding. Replay
checks deterministic implementation fidelity; it is not a fourth causal arm.

`response_token`, whose value must be one of the episode's two canonically
