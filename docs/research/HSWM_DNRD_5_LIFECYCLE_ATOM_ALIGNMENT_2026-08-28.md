## Target identity, current evidence, and conceptual delta

The target is still one token-native LLM-function macro-neural network whose
schema-admitted evolving hypergraph is simultaneously living harness, world
model, and continuous learner.  A lifecycle log or KG view is only a bounded
projection of that state.  It is not cognition, ownership, admission, or
learning by itself.

The current DNRD-5 lifecycle instrument validates an exact chronology of 15
events, 59 artifact descriptors, 27 artifact kinds, and nine generation-call
slots.  Its seal chain closes descriptor manifests.  It contains no canonical
atom key, sole responsibility owner, typed references, provenance, or admitted
content bytes.  The canonical schema validates those properties separately.
Consequently, calling the lifecycle vector a canonical-atom closure would be a
category error even though both validators pass.

The conceptual delta is to make lifecycle rows explicitly non-authoritative
projection records and to require an adapter from each row to admitted atoms
or atom-derived slots before constructing a production-shaped byte corpus.
No owner is assigned to a projection row merely because its uppercase name
resembles a canonical kind.

The lifecycle artifact count is:

```text

```

The mapping classes are:

| Class | Artifact rows | Meaning |

| Direct kind candidate | 46 | The lifecycle concept has a canonical kind, but the row still lacks an atom key, owner, provenance, typed references, and actual content binding. |
| Four-slot assignment projection | 4 | Four arm rows must project one `block_assignment` atom plus four distinct `fork_incidence` refs; they are not four assignment atoms. |

| Missing canonical kind | 1 | Delayed audit disclosure has an information/authorization effect but schema v1 has no owned atom kind for it. |

All 59 rows therefore remain unbound projections.  The alignment contract
rejects promotion of any row to an authoritative or closure-ready record.

### Assignment

There is exactly one `block_assignment` atom per block.  It must reference the
study randomness, block specification, and four distinct sealed forks while
its content closes the complete four-arm permutation.  Each of the four
lifecycle rows will later carry a non-authoritative slot projection referencing
that one assignment and its one fork.  Four labels without these refs are
insufficient.

### Arm transition

`ARM_TRANSITION` remains a derived readout, not a new canonical kind.  Its
future adapter must bind the exact arm-dependent source set:

- ACTIVE and SHAM: validation, credit decision, one-shot capability
  consumption, transition receipt, and admitted macro disposition;
- DELAYED: validation and a no-admission credit decision, with its proposal
  quarantined and no transition receipt; and
- ROLLBACK: the admitted source set plus the exact-W0 restore transaction.

If this projection is ever allowed to authorize an effect or gain an
independent revision/rollback lifecycle, it must instead become its own owned
canonical atom.  The present contract forbids that authority.

### Probe response

`PROBE_RESPONSE_SEAL` is not silently renamed to `probe_trajectory`.  The
future adapter must show that each seal's actual request/response bytes and
runtime provenance are the content bound by one probe-trajectory atom, which
itself references the correct probe commitment and behavior projection.

### Delayed audit release

Unlike the derived arm summary, delayed outcome disclosure has an information
and authorization effect.  The present `hswm:dnrd5:causal-macroplasticity:v1`
schema has no kind for it.  That version is preserved rather than semantically
rewritten in place.  A successor schema must introduce an `audit_release` atom
with its own responsibility owner and references to the hidden outcome,
escrow, all four probe trajectories/outcomes, and current capability,
authorization, and revocation records.  Its block seal must also reference the
release.  Until then, the one lifecycle row is classified
`CANONICAL_KIND_MISSING`.

## Remaining canonical support and block-seal gap

Ten support kinds are required by the schema's reference closure but are not
lifecycle artifact kinds: `permit_policy`, `authorization_decision`,
`capability_issuance`, `revocation_status`, `evaluator_capability`,
`grant_snapshot`, `capability_consumption`, `restore_policy`,
`macro_disposition`, and `projection_policy`.  They may be pre-existing or
block-local in the eventual occurrence, but their exact atoms and content
descriptors must be bound rather than inferred from lifecycle labels.

The current `block_seal` contract references only the block specification, one
assignment, and four probe outcomes.  It does not reference the delayed audit
release and still does not close every admitted block atom, the complete
nine-call provider ledger, all 15 event seals, actual content bytes, or the
projection-to-atom bindings.  It is therefore intentionally classified
`INSUFFICIENT_FOR_PRODUCTION_BLOCK_CLOSURE`.

The audit also exposed a transaction-chronology boundary that must be repaired
before actual-byte construction.  The generic canonical transaction kernel
already admits same-command references and rejects cyclic provenance across the
combined pre-state and write batch.  The v1 DNRD chronology checker instead
validates a flat sequence of already-materialized atoms, while the durable
admission grammar atomically writes capability consumption, transition receipt,
and macro disposition.  Those two instruments answer different questions.  A
successor DNRD schema must retain the one-CAS effect, validate intra-batch
dependencies explicitly, and distinguish a pre-commit admission decision from
a post-commit receipt that binds the recovered journal record.  Neither the
generic kernel nor the v1 chronology checker should be weakened or relabeled.

## Falsification requirements for the next slice

The production-shaped adapter must refuse at least these attacks:

1. four assignment rows with a repeated or missing fork;
2. four arm labels without one valid assignment atom and complete permutation;
3. a lifecycle row whose referenced atom has the wrong kind, owner,
   provenance, content descriptor, or typed-reference cardinality;
4. a delayed release that fails to bind all four sealed probes/outcomes and a
   current scoped authority chain;
5. an arm-transition projection used as admission or restore authority;
6. a descriptor/seal chain that stays valid while an atom reference or actual
   byte blob is changed; and
7. any projection-only corpus relabeled as Permit, occurrence, causal-learning,
   or efficacy evidence.

Passing the Python and TypeScript alignment checks establishes only that this
mapping and its gaps are represented consistently.  It is not Source-A
qualification, an occurrence, or a scientific result.  Model-call count
remains zero.
