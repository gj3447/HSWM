## Target identity, current evidence, and conceptual delta

HSWM's target remains one token-native LLM-function macro-neural network whose
schema-admitted evolving hypergraph is simultaneously its living harness,
world model, and continuous learner.  DNRD-5 is a bounded falsifier for one
link in that identity: whether independently attributable outcome information
can cause a permitted canonical macro-disposition revision that changes a
later hidden-probe transition.  Repository ontology, KG projections, lifecycle
tables, source manifests, and tests are evidence instruments and interfaces;
they are not that cognition or learning loop.

The current evidence does not answer the causal question.  The deterministic
one-block corpus closes one fixture's actual bytes under an independent judge,
but its source, build, import, Permit, and provider fields were placeholders.
The conceptual delta here is therefore not another harness feature.  It is a
fail-closed instrument that derives the exact local source/toolchain/build
surface that a later Source-A decision would have to bind, while issuing no
Source-A authority and performing no occurrence call.

## Candidate closure

The producer in `_research/dnrd5/source_build_import_closure.py` performs the
following local-only derivation:

1. It requires a detached checkout whose `HEAD` equals the requested commit
   and whose Git porcelain status is empty apart from ignored build inputs.
2. It disables Git replacement objects, reads raw commit, tree, subtree, and
   selected blob bytes, recomputes their native Git object IDs, parses the raw
   binary tree entries and modes, and separately records SHA-256 descriptors.
3. It requires every selected worktree byte to equal its raw Git blob and
   rejects leaf or parent symlink traversal.
4. It parses the complete tracked `_research/dnrd5/**/*.py` set without
   importing it, rederives static imports and syntactic call sites, rejects
   dynamic-loader roots and common alias paths, and exposes `socket`, `ssl`,
   `http`, and `urllib` imports as network-capable deferred code rather than
   hiding them.
5. It installs the locked npm graph in a temporary detached clone with npm
   offline and lifecycle scripts disabled, then invokes the checked-in Node
   capture script itself.  Caller-supplied TypeScript reports are not accepted
   by the production capture path.
6. The Node instrument uses the pinned TypeScript `Program` resolution table,
   requires eight exact DNRD-5 entrypoints, rejects runtime loaders and loader
   aliases conservatively, captures all selected local and external compiler
   files, emits into a checkout-location-independent temporary directory, and
   hashes the complete regular-file output tree before deleting it.
7. Python independently canonical-parses the Node bytes, recomputes the output
   descriptor root, enforces the exact compiler policy and sole internal
   durable-commit seam importer, and physically rehashes every input, compiler,
   external, source, and import-target descriptor in the detached checkout.
8. An independently implemented Python judge consumes only the canonical
   manifest contract.  In physical mode it separately walks raw Git objects,
   rederives the selected worktree and Python AST evidence, and rehashes the
   recorded Node/Python executables and every recorded TypeScript descriptor.
   It deliberately does not claim an independent compiler-semantic proof or a
   second rebuild of the emitted bytes.
9. The resulting manifest binds the schema, lifecycle/alignment, plan KAT,
   actual-byte corpus, Python and npm lockfiles, Node/Python executable bytes,
   source graph, build tree, and explicit zero-call claim boundary.

The raw generic durable `submit()` surface now also refuses both DNRD-5 v1 and
v2 schema identities with `DNRD5_PERMIT_DISPATCH_REQUIRED`.  This prevents the
ordinary checked runtime path from treating v2 writes as generic submissions;
it does not yet create a v2 Permit dispatcher.

## What this can and cannot establish

If the detached capture and its independent structural judge pass, the result
may establish that one exact local commit, locked toolchain, selected import
graph, and emitted tree were bound consistently by the checked instruments.
It still cannot establish:

- compiler or interpreter soundness;
- semantic import/call analysis of every hash-selected test, workflow, or
  capture-script byte outside the complete DNRD-5 Python AST set and the exact
  TypeScript `Program` selected by the eight entrypoints;
- remote package provenance merely from a warm offline npm cache;
- absence of every possible network syscall or hostile modified executable;
- a trusted Source-A authority, CI/source-freeze decision, or occurrence root;
- canonical Permit, provider-side exactly-once behavior, or a provider event;
- outcome independence, causal learning, utility, or HSWM efficacy.

In particular, `_research/dnrd5/provider_gateway.py` deliberately remains
classified as network-capable deferred code.  Its existing raw v1-compatible
`execute` surface does not accept a v2 occurrence capability and is not yet a
sole dispatcher.  A source closure must expose that gap, not relabel it as a
success.
