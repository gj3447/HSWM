## 1. Answer first

**Graph engineering should be much stronger in the HSWM research path.** The repository has n-ary hypergraph prototypes, incidence/traversal readouts, immutable snapshots, SQLite commits, typed cell ports, and an outcome/revision research program. They are not yet one source-bound graph runtime with a native canonical plane, declared compiled projections, transactional rewrites, conflict handling, incremental materialized views, and causal intervention receipts.

**Loop engineering is partially present, but not yet an integrated research/runtime control loop.** Here it means a bounded cycle that selects work, loads an identified state, acts, observes an independent result, verifies it, records a disposition, and stops, retries, or escalates by an explicit rule. The name is a new practitioner term, not an established scientific standard. The underlying feedback, state, budget, evaluation, recovery, and stop concerns are well-established engineering practices.

Neither layer is HSWM cognition. A graph database, KG, or workflow can hold a projection or run an experiment; only the outcome-bound loop below could support a bounded learning claim, and then only after its declared interventions pass.

## 2. Canonical role, evidence, and delta

| layer | statement |
|---|---|
| target identity | One token-native LLM-function macro-neural HSWM whose evolving schema-approved canonical atoms and typed relations play the roles of living harness, world model, and continuous learner. |
| current evidence | Local engineering supports some admission, replay, budgets, snapshots, typed ports, and bounded graph readouts. It does not establish outcome-bound causal revision, learned topology, integrated living-harness utility, or composition. |
| conceptual delta | Treat graph representation, graph execution, graph mutation, loop control, and scientific evaluation as source-bound contracts connected by outcome-bound transition lineage—not as a growing static controller around an LLM. |

The delta preserves the Constitution: a KG, RAG, ontology, prompt, agent workflow, or graph database is storage, projection, or I/O and cannot substitute for causal learning. It also preserves the adaptive strategy: graph backend and loop realization are replaceable mechanisms, not target identity.

## 5. Reinforced graph contract

The following are views and contracts of one HSWM state, not new cognitive subsystems.

| plane | minimum contract | required evidence before promotion |
|---|---|---|
| canonical n-ary state | Versioned atom, reified hyperedge/incidence, typed reference, schema-relative owner, source/authority/lineage, explicit lifecycle. | Shape validation and lossless source/restore round trip. |
| compiled graph | Source snapshot, compiler version, mapping/loss declaration, sparse incidence/index, expiry/invalidation rule. | Exact replay and stale/tamper refusal. |
| graph transaction | Proposal, match, precondition, authority, conflict policy, candidate epoch, commit/reject/quarantine/restore receipt. | Concurrent conflict and recovery tests. |
| graph readout | Query intent, graph cut, serialization budget, omitted information, traceable use in an action. | Native-vs-compiled and lossy-projection controls. |
| graph intervention | Identified add/remove/split/merge/specialize/restore delta and compiled mediation path. | Pre-registered held-out effect, removal loss, restoration, and matched alternatives. |

First implement a **canonical-to-compiled projection manifest**. Every execution edge or sparse entry must identify its source atom/incidence version, declared loss, write-back permission, and invalidation condition. No clique, embedding, graph-database view, or LLM serialization can silently become canonical state.

Second implement a **typed graph-delta transaction**. It must fail closed if source state, schema, owner, permit, match, dangling context, critical-pair policy, compiler mapping, or restore receipt is missing. A database transaction is useful but does not replace these semantic conditions.

## 6. Reinforced loop contract

The relevant loop is neither an uncontrolled autonomous-research daemon nor a static script that dictates HSWM cognition:

```text
triggered research/episode contract
  → load exact canonical snapshot and compiled projection
  → LLM token/action/tool trajectory under capability and budget limits
  → seal trajectory before outcome
  → independently grounded outcome and declared causal credit
  → proposed graph/relation/disposition delta
  → independent validation plus Permit/Inv and graph-transaction decision
  → commit, reject, quarantine, or restore with receipt
  → replay fresh held-out behavior and evaluate removal/restoration
  → machine stop, bounded retry, or explicit human escalation
```

The execution verdict, state-transition verdict, and research verdict are separate. Execution success cannot approve a graph delta; a committed delta cannot claim efficacy. Failed or inconclusive research must update the mechanism disposition and next contract, never rewrite the evaluated result.

## 7. Staged path

| ID | deliverable | falsifier / stop condition | ceiling |
|---|---|---|---|
| `GE-0` | Schema-relative canonical n-ary atom and incidence contract. | A record cannot round-trip, has ambiguous ownership, or silently aliases a projection. | `GRAPH_STATE_CONTRACT_ENGINEERING_ONLY` |
| `GE-1` | Canonical-to-compiled manifest, deterministic replay, stale/tamper refusal. | Entries cannot be traced to source versions and declared loss. | `COMPILED_GRAPH_TRACEABILITY_ENGINEERING_ONLY` |
| `GE-2` | Typed delta transaction with conflict, quarantine, restore, and concurrent-edit tests. | A rejected/competing delta changes state or recovery loses lineage. | `GRAPH_TRANSACTION_ENGINEERING_ONLY` |
| `LE-0` | Loop controller recording trigger, snapshot, budget, verifier, stop/retry/escalation, and all verdicts. | It can run unbounded, self-approve, erase a failure, or silently change contract. | `LOOP_CONTROL_ENGINEERING_ONLY` |
| `GL-1` | Pre-registered G1: outcome-bound graph revision mediates fresh held-out behavior and loses/recovers effect under remove/restore. | Matched RAG, lesson, static workflow, sham, shuffled credit, or fixed graph explains gain. | Existing G1 ceiling only if G1 passes. |
| `GL-3` | Later G3 topology morphogenesis and recovery experiment. | Fixed topology, matched random rewiring, or manual central repair explains result. | Existing G3 ceiling only if prerequisites pass. |

`GE-*` and `LE-0` are engineering qualification only. `GL-*` remains subject to the existing G0–G6 order; downstream scale cannot rescue a failed local causal rung.
