# ICE 실사용의 한계를 해결하는 HSWM 학습 설계

2026-09-08 · `SECONDARY_AI / DESIGN_PROPOSAL / PROPOSED_NOT_IMPLEMENTED`.
코드 검토 기준: HSWM `528f4a3eafe5f84488432e6a979d240d06268f61`.
출발 근거는 [ICE 소비자 평가](../operations/HSWM_ICE_CONSUMER_FEEDBACK_2026-09-08.md)와
그 [고정 KG 기록](../../ontology/evidence/HSWM_ICE_CONSUMER_FEEDBACK_2026-09-08.v1.json)이다.
사용자는 앞선 AI 분석을 인용하여 해결안을 숙고하고 KG에 정리하도록 요청했다.
그 인용을 새로운 사용자 실측이나 아래 상세 설계의 `USER_PRIMARY` 확정으로 승격하지 않는다.

**권고:** 실제로 대체 가능한 접근에서 경험이 선택에 개입하게 하고, 평가한 산출물에만
피드백을 결속한다. 작은 표본의 영향과 사용 비용을 함께 제한한다. 다음 과제의 질문·근거·행동이
바뀌는 경로와 그 결과를 확인해야 하며, 점수·기록·KG 항목의 증가는 그 대리 지표가 아니다.

## 정체성과 개념적 변화

[Constitution](../canon/HSWM_CONSTITUTION_2026-08-20.md)의 하나의 token-native LLM-function
macro-neural HSWM, 같은 evolving hypergraph가 living harness·world/self model·learner의
역할을 함께 한다는 목표를 유지한다. [적응 연구 전략](../canon/HSWM_ADAPTIVE_RESEARCH_STRATEGY_2026-08-30.md)과
그 [온톨로지](../../ontology/identity/hswm_core/HSWM_ADAPTIVE_RESEARCH_STRATEGY_ONTOLOGY.v1.json)의
목표/방법 구분, 기존 FCL-1..8 계약·실패·미판정 상태도 유지한다.

개념적 변화는 **과제 종류를 배정하는 규칙의 성공 횟수를 세는 데서, 동일한 목적 아래 경험이
관찰·질문·행동을 어떻게 수정해야 하는지 판별하는 데로 학습의 위치를 옮기는 것**이다.
허용 조건, 선택 성향, 관측, 평가, 수정 후보는 구별되는 역할이며 새 고정 subsystem이 아니다.
각 schema-approved atom의 단일 책임 owner와 typed reference, 출처·outcome에 결속된 revision으로
실현해야 한다. 현재 local adaptive store는 canonical admission이나 인과 credit 경로가 아니다.
KG에 이 설계를 게시하는 것도 그 경로를 구현하는 행위는 아니다.

## M1. 유효한 대안 사이에서 학습한다

처음에는 ICE investigate 과제의 읽기 중심 구간 하나를 고른다. 필요한 정의역·자료 접근
전제를 확보한 뒤 `기존 반례의 조건 적합성부터 확인`과 `새 반례 구성부터 시도`를 같은
완료 기준 아래 대안으로 둔다. 동일한 모델·도구 접근·전체 예산을 제공하고, 각 접근이 읽는
자료와 순서는 행동의 일부로 기록한다. 실행 불가능한 가짜 대안을 만들지 않는다.

필수 조건은 다음과 같다.

- 선택 직전 eligible 후보 전체, 탈락 사유, 관계 revision, 점수와 tie 여부를 기록한다.
  후보가 하나면 `SINGLE_ELIGIBLE / SELECTION_EFFECT_NOT_IDENTIFIED`로 분류한다.
- 필수 전제·타입·권한·예산 조건을 학습 점수가 우회할 수 없다. 학습된 child 조건은 부모의
  필수 조건을 보존해야 한다. 설계상 `eligibility AND learned_condition`의 역할을 분리한다.
- 첫 비교에서는 동등한 후보에 사전 지정한 소량의 무작위 배정을 적용하고 실제 배정 확률을
  남기는 방식을 후보로 둔다. 현재의 결정적 score/UID 정렬이나 탐색 bonus를 randomized
  exploration·통계적 신뢰구간으로 부르지 않는다. 후보 강제 실행은 실행 가능성 확인이지
  학습 선택의 우위 증거가 아니다.
- 선택하지 않은 행동의 결과는 미관측이다. 다른 과제의 결과를 반사실 정답으로 채우지 않는다.
  off-policy 비교에는 실제 기록 정책과 action support가 필요하다. 소수 로그의 중요도 가중치로
  바로 효능을 확정하지 않는다.

**반박 조건 F1:** 후보 차이가 이름뿐이거나, 둘 중 하나만 유효하거나, 비교군에 도구·자료·시간을
덜 주었다면 선택 효과의 평가 설계가 성립하지 않는다. 민감한 과제에서 관계 remove/restore가
선택·관측을 바꾸지 않는다면 그 범위의 상태 매개가 관측되지 않은 것이다. 단일 실행이나
불확실성이 큰 소표본으로 일반적 무효 판정을 내리지 않는다.

**I6의 선행 수정 후보:** `proposeSpecialization`은 부모 digest 문자열만 받고 부모 guard를
받지 않는다. `adaptive-runtime.ts`의 자동 outcome 및 사후 feedback 경로 모두 새 관계에
`guard: proposal.right.relation_ast`와 `active: true`를 쓴다. 따라서 `PROPOSED_NOT_ADMITTED`라는
proposal label만으로 local 실행이 억제된다고 해석할 수 없다. 부모 guard가 FALSE이고 학습
조건이 TRUE인 문맥에서도 child가 탈락하도록 유한 domain의 진리표를 확인해야 한다.
부모의 필수 조건 보존 또는 명시적 `all(parent_guard, learned_condition)` 합성을 우선한다.
이것은 관계 적용 범위와 평가 타당성의 문제이며, 다른 capability 검사의 우회까지 입증한 것은 아니다.

## M2. 표현 크기와 경험 신뢰도를 분리한다

서로 다른 문제를 두 단계로 다룬다. 첫째는 feature 수에 따른 한 번의 갱신 크기이고,
둘째는 적은·상관된·편향된 피드백으로부터 얼마나 믿고 선택할지다.

첫 수정 후보는 활성 feature 수 `m`으로 각 feature의 갱신량을 나누는 국소 갱신이다.
현재 이진 feature 표현에서 clipping 전 같은 문맥의 logit 총변화는 기존 `m × rate × error`에서
`rate × error`가 된다. 이것은 해당 표현에서의 대수적 성질이며 일반적 최적화 보장은 아니다.
관측 수·수렴 속도·교호작용 학습과 다른 문맥에 전이되는 크기도 변하므로 원래 규칙과 비교한다.
입력 vector 자체를 정규화하는 방법, L2 규제는 별도의 후보이며 동시에 섞어 원인을 흐리지 않는다.

두 번째 후보는 표본 수와 문맥 범위를 표시하면서, 경험이 적을 때 학습 점수가 기존 선택에
주는 영향을 완만하게 늘리는 것이다. 임의의 최소 표본 수를 넘었다고 보정 확률로 승격하지 않는다.
중복 review 제거와 동일 과제·동일 실패의 묶음 식별이 먼저이며, 같은 결과의 재평가를 독립
성공 횟수로 세지 않는다. 전역 `n`만으로 학습률이 감소하면 새 문맥의 적응이 약해지는지도 본다.

최소 판별은 같은 숨은 원인·같은 결과 순서에서 무관 필드만 늘린 표현과, 실제 교호작용이 필요한
표현을 함께 비교하는 것이다. held-out label이 있는 경우에만 log loss/Brier와 선택 품질을 본다.
작은 수치나 평탄한 곡선 자체를 개선으로 세지 않는다. 64개 feature·64개 context 한도에 따른
학습 거절도 별도 집계하여 어려운 사례를 조용히 탈락시키지 않는다.

**호환성:** 새 갱신 규칙에는 새 learner identity/version이 필요하다. v1 가중치를 새 의미로
조용히 재해석하거나 과거 SQLite revision·digest를 다시 쓰지 않는다. 새 상태에서 시작하는
방법을 기본 후보로 두고, 이력이 충분하면 고정 원자료의 명시적 replay migration을 검토한다.
모든 variant는 동일한 학습 이력·자원으로 비교하고 migration 비용을 포함한다.

**반박 조건 F2:** 점수 포화만 완화되고 처음 보는 과제의 품질·선택이 악화되거나, 필요한
교호작용을 잃거나, 새 문맥에서 적응이 지나치게 늦어지면 그 후보 규칙을 수정·폐기한다.
정규화는 인과 credit이나 보정 확률을 자동 제공하지 않는다.

## M3. 평가한 산출물과 선택 발생 지점에 피드백을 결속한다

후속 API 후보는 `review_id`, episode, trajectory occurrence, 선택한 관계 UID/revision,
실행 당시 모델·learner 버전, 산출물 digest, 평가 계약/rubric 버전·digest, 결과,
검토자 출처, 근거 참조를 받는다. 이는 설계 필드이며 현 CLI에 존재하는 옵션이 아니다.
root 전체 평가, 단계별 계약 평가, 특정 행동의 인과적 기여 평가는 서로 다른 대상이다.

처리 계약은 다음과 같다.

1. episode에 속한 정확한 immutable trajectory와 실행 당시 관계·산출물을 조회한다.
   완료 여부와 평가 가능한 산출물의 무결성을 확인한다. 추론이 틀린 완결된 산출물은 유효한
   부정 label이 될 수 있다. transport 실패·잘림·산출물 부재는 내용 정확성의 부정 label이 아니다.
   인프라 실패를 학습하려면 그 결과를 정의한 별도 평가 대상과 계약을 사용한다.
2. 평가한 출력이 해당 occurrence의 출력인지 검증한다. leaf가 관계를 선택하지 않았다면,
   leaf 평가를 허구의 leaf 관계 갱신으로 바꾸지 않는다. 그 관측을 보존하고, 정의된 local
   평가 대상과 연결된 선택 occurrence가 있을 때만 해당 관계의 갱신 후보로 쓴다.
3. 같은 review ID와 같은 정규화 요청은 원래 receipt를 반환하고, 다른 내용이면 충돌로
   처리한다. 같은 산출물·평가 계약을 다른 ID로 다시 제출해도 독립 경험을 늘리지 않는다.
   사람의 평가 수정은 이전 평가를 지우지 않는 superseding review이며, 단순 추가 reward가 아니다.
4. 실행 이후 관계·learner·평가 의미가 바뀌었다면 최신 관계에 옛 label을 바로 쓰지 않는다.
   원래 revision에 귀속된 관측을 보존하고 명시적 호환성 판단/replay가 있을 때만 갱신한다.
   늦은 평가를 전부 버리거나 진행을 막는 전역 승인 절차로 만들지 않는다.
5. 평가한 대상의 관계만 원자적으로 갱신하고 근거 계보를 남긴다. root·다른 단계·다른 과제에
   성공을 배분하지 않는다. 미평가 단계는 미평가로 남긴다. 복수 평가자의 상관된 평가도
   독립 경험 여러 건으로 계산하지 않는다.

**반박 조건 F3:** 출력·관계 revision이 다른 평가를 받아들이거나, 재전달로 두 번 학습하거나,
평가하지 않은 관계를 바꾸면 구현 계약 실패다. 단계별 평가가 정상 작동해도 인과 기여는
`UNIDENTIFIED`로 남는다. 기여도는 replay 가능한 작은 구간에서 같은 prefix·환경 snapshot·
후속 정책을 고정하고 해당 행동만 바꾸는 별도 비교 후보로 다룬다. 이후 산출물은 새로
생성되므로 동일한 미래 transcript를 강제로 붙이지 않는다.

## M4. 더 좋은 다음 질문과 근거를 만들게 한다

Boolean은 관측과 실행의 성공 여부를 전달하지만 수정 방향까지 설명하지 못한다.
실패를 `어떤 주장/조건이`, `어떤 산출물·근거와`, `어떻게 충돌했는지`로 구조화하고,
그로부터 `조건 수정`, `추가로 읽을 근거`, `다음 질문`, `행동 순서`의 작은 후보를 제안한다.
각 후보에는 predecessor revision, 필요한 외부 관찰, 예상 변화, 실패 판별 기준을 붙인다.
LLM이 쓴 그럴듯한 회고는 수정 가설이며 독립 정답이 아니다.

ICE 예시는 과거 반례가 특정 경계조건에서 실패했다는 근거를 참조하여, 다음 유사 목표에서
그 경계가 성립하는지 먼저 묻는 것이다. 최종 문장의 유창함보다 실제 누락 조건 발견·오탐·
개발자가 추가 설명한 횟수와 시간을 평가한다. 질문을 더 많이 만들면 비용도 증가한다.
현재 scalar `reads` 목록 변경과 실제 원문 resolver 조회 변화는 별도다. 조회한 자료의
버전·digest·범위와 다음 행동 trace가 함께 있어야 근거 선택 변화라고 주장할 수 있다.

**반박 조건 F4:** 질문은 달라졌지만 실제 조회·행동이 같거나, 정답을 암시하는 누출이 있거나,
틀린 회고가 이후 결정을 악화시키면 그 후보의 주장이 지지되지 않는다. 결과를 본 뒤 질문을
좋았다고 재서술하는 대신 질문·예측을 outcome 이전에 고정한다.

## E1/E2. 두 가지 효과를 다른 비교로 판별한다

| 평가 대상 | 고정하는 것 | 변화를 허용하는 것 | 해석 |
| --- | --- | --- | --- |
| E1: 질문을 받은 뒤의 실행 선택 | 질문, 사용 가능한 자료, 후보 정책, 모델·도구, 총예산, 평가 기준 | 경험 상태에 따른 선택. 후보에 정의된 read/action 차이 | 동일 질문 아래 국소 선택의 추가 효과 |
| E2: 연구 목표를 받은 뒤의 전체 효과 | 상위 목표, 사용 가능한 자료, 모델·도구, 총예산, 평가 기준 | 다음 질문, 실제 읽을 자료, 순서와 관계 선택 | 질문 생성까지 포함한 HSWM의 추가 효과 |

E2에서는 최종적으로 읽은 자료나 사람이 만든 상세 질문까지 고정하면, 평가하려는 학습의
작동 경로를 막는다. 사용 가능한 corpus는 같게 하고 실제 read-set은 비용·결과와 함께 관측한다.
질문 생성 자체의 효과를 따로 보려면 downstream 정책을 고정한 별도 부분 비교를 한다.
질문과 routing이 모두 변한 결과를 routing 단독의 인과 효과로 부르지 않는다.

실행 가능한 종료 사례 일부에서 같은 모델의 native agent+같은 이력, frozen HSWM,
학습하는 HSWM을 비교한다. 각 arm의 상태와 workspace를 분리하고 평가 task를 경험 학습에
다시 넣지 않는다. frozen은 보상뿐 아니라 비용 통계·탐색 횟수·조건 합성 등 선택에 영향을
주는 모든 state가 고정됐는지 점검한다. native agent의 기본 memory·tools를 억지로 빼지 않는다.
동일 이력의 평문 제공은 별도 진단 대조다. typed relation의 구조 효과와 경험 정보량을 구분한다.

평가 데이터가 없는 첫 5~10개 사례는 선택·재현·평가·비용 측정이 가능한지 보는 pilot 후보다.
그 숫자는 충분한 표본 수나 효능 통과 기준이 아니다. 실제 품질을 판별할 rubric과 외부 검사,
과제 가족 단위의 holdout, 모델/도구 snapshot을 먼저 정한다. 검토자는 가능한 범위에서 arm과
자기 설명을 가리고 산출물·원근거를 평가한다. 반복 paraphrase를 새로운 독립 과제로 세지 않는다.

실사용을 막지 않고 종료한 사례 일부만 replay한다. 운영 학습의 시간순 평가는 당시 이용 가능한
과거 평가만 다음 과제에 사용하고, frozen holdout 평가는 평가 label을 학습으로 돌리지 않는다는
서로 다른 protocol로 둔다. 샘플링 규칙·최소 실질 효과·허용 품질 손실·총비용·중단 규칙은 결과
전에 정한다. 간헐적 재확인마다 유리한 순간에 종료하는 유의성 판단은 피한다.

넓은 불확실성, 포화된 과제, 선택지 부재는 `UNDERDETERMINED` 또는 미식별이다.
유효하고 민감한 비교가 사전 지정한 실질 효과를 배제할 때만 정확한 기전과 범위를
`RED_WITHIN_SCOPE`로 종료·교체한다. 유효한 음성 결과를 더 큰 KG나 상위 합성으로 구제하지 않는다.
작은 개선도 그 범위의 결과이며 HSWM 전체나 다른 agent 도구 대비 우위로 일반화하지 않는다.

## M5/E3. 사용 비용과 모델 교체를 포함한다

매 과제에 새 긴 설문을 추가하는 대신 기존 trace에서 자동 수집할 수 있는 필드부터 쓴다.
실행 시간, 모델/effort·usage, 조회·도구 호출, 실패·재시도, 수정한 파일/산출물, 평가 provenance를
기록하고, 사람에게 필요한 것은 추가 설명·검토·수정에 실제 쓴 시간 등 자동으로 알 수 없는 부분이다.
모르는 비용은 0이 아니라 미측정으로 둔다.

초기 연결·schema 매핑·migration 비용과 반복 token·지연·검토·복구 비용을 분리한다.
같은 품질 기준에서 반복 절감이 양수일 때만 `초기 비용 / 과제당 반복 순절감`으로 회수 과제 수를
추정할 수 있다. 시간과 금액은 별도 단위로 보고하고, 합칠 때만 가치 환산 기준을 사전에 명시한다.
반복 절감이 0 이하이면 이 조건에서 회수가 안 되며, 초기 구축비를 중복 가산하지 않는다.

**반박 조건 F5:** 같은 품질의 결과를 얻는 데 반복 비용·사람의 설명/수정 부담이 더 크거나,
초기 비용의 회수 가능성이 관측 범위에서 없으면 개발 도구로서 그 설정을 유지할 이유가 약해진다.
연구를 계속할 가치는 별도 판단이며 실제 절감으로 기록하지 않는다.

모델·harness·도구 버전이 바뀌면 외부 사실과 그 모델에서 통했던 전술을 구분한다.
새 모델+옛 상태, 새 모델+재검토한 상태, 새 모델+같은 이력의 native 접근을 작은 동일 사례에서
비교하는 것은 migration 후보 평가다. 나쁜 전이를 일으킨 전술을 자동 승계하지 않는다.
새 모델 단독과 옛 모델+HSWM의 비교는 투자 대안 비교이며 HSWM 단독의 인과 효과가 아니다.

## 다음 구현의 순서와 완료 조건

다음은 후속 작업 제안이며 이번 문서/KG 작업에서 runtime을 바꾸지 않는다.

1. **선택과 평가 가능성 확보:** I6의 부모 조건 보존을 먼저 닫고 실제 대안 한 쌍, 결과 전 candidate/trace 기록, 얇은 비용 기록을
   연결한다. 필수 검사를 생략하는 쉬운 경로를 더 좋은 학습 경로로 보상하지 않는다.
2. **작은 학습기 비교:** 새 version으로 M2 후보 하나를 구현해 원래 규칙과 비교한다.
   실제 성공 피드백을 조작하거나 기존 이력을 덮어쓰지 않는다.
3. **산출물별 피드백:** M3의 identity·중복·stale 처리와 갱신 대상 분리를 연결한다.
   root 전체 평가가 필요한 기존 사용법도 유지한다.
4. **질문/관계 수정 후보:** M4를 실제 evidence resolver·행동 trace에 연결한다.
   E1/E2를 구분해 끝난 사례 일부에서만 비교한다.

새 구현은 `src/hswm/effect-runtime/src/`에서 순수 상태 계산과 typed Effect I/O로 발전시킨다.
검사는 입력 불변성·정확한 피드백 귀속·중복 처리·과거 상태 보존 같은 구현 계약을 판별한다.
그 통과와 실사용 순효용·인과 학습의 판정은 별도다. 추가 서버·DB·MCP를 도입하는 것이 이
문제의 선행 조건은 아니다. 현재 native CLI와 로컬 저장으로 좁은 실사용 비교를 시작할 수 있다.

## KG에서 찾을 관계

동명 ontology bundle은 `확인된 한계 → 해결 후보 → 적용 경계 → 판별 방법/반박 조건 → 근거`를
연결한다. I1..I6, M1..M5, E1..E3, F1..F5를 구분하고, 과거 ICE 관측·정전·코드·문헌 출처에
고정 참조를 둔다. 모든 새 설계 판단은 `SECONDARY_AI`이며, 기존 고정 snapshot은 보존한다.
게시·SHACL·readback 성공은 이 지식의 정합성 검증이고 학습 기전의 실행·효능 증거가 아니다.
