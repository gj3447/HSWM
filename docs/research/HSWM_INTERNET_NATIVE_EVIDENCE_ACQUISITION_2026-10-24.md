# HSWM의 검색 충분성·외부 획득 시점·인터넷 참여

2026-10-24 · `agent(codex) / SECONDARY_AI_DESIGN`.
방향의 출처는 [이번 사용자 원문](../canon/sources/USER_PRIMARY_HSWM_INTERNET_NATIVE_2026-10-24.md)과
[인간·LLM을 활성 주체로 보는 기존 원문](../canon/USER_PRIMARY_HUMAN_UNIVERSAL_BODY_DISTINCTION_2026-08-20.md)이다.
이 문서는 [헌법 4–6조](../canon/hswm/activation.md), [9조](../canon/hswm/learning.md),
[12조](../canon/hswm/composition.md)를 실행 가능한 계약으로 구체화한다. 아래 상태 이름·
선택 절차·어댑터는 설계안이며 새 native runtime이나 상시 인터넷 서비스를 구현했다는 보고가 아니다.

## 1. 목적과 해결할 문제

HSWM은 자신의 판단에 무엇이 부족한지 드러내고, 필요한 때 외부의 지식·사건·사람의
정정을 받아 다음 판단을 바꾸어야 한다. 인터넷의 변화와 사람의 참여를 지속 상태의
관측·관계·작업으로 연결하며, 결과도 해당 참여자가 이해하고 정정할 수 있게 돌려준다.

현재 검색 결과가 주제와 비슷해도 필수 전제·예외·현재 판본이 빠질 수 있다. 반대로
근거가 충분한데 계속 검색하면 비용·지연·무관한 주장만 늘어난다. 자료가 충분하지만
추론이 틀린 경우에는 같은 검색을 반복하기보다 추론·실행을 고쳐야 한다.
‘관련성’, ‘이 과제의 근거 충분성’, ‘출처의 사실성’, ‘답변의 정답 여부’를 따로 판정한다.[S1]

## 2. 무엇이 부족한지 표현한다

질문·예정 행동에서 필요한 근거 항목을 먼저 만든다. 예를 들어 ‘이 장비에서 API X를
사용할 수 있는가’에는 장비/설치 판본, API 제공 조건, 예외, 실제 접근·실행 결과가 필요하다.
각 항목에는 필수/보조 구분, 대상·범위·기준 시각, 어떤 원문이 어느 부분을 뒷받침하는지를 둔다.
첫 분해도 틀릴 수 있으므로 새 예외·반례를 발견하면 항목을 추가하거나 재구성한다.

| 부족함 | 관측할 근거 | 보완 방향 |
| --- | --- | --- |
| 필요한 사실·역할·예외 누락 | 필수 항목에 대응하는 원문 구간이 없음 | 해당 구간을 찾아 읽기; 외부에만 있으면 획득 |
| 관련 문서는 있으나 답을 지지하지 않음 | 인용 구간이 주장·조건을 실제로 설명하지 않음 | 질문을 누락된 관계 중심으로 다시 구성 |
| 정보가 오래됐거나 시점 미상 | 필요한 기준 시각과 관측/판본/유효기간이 맞지 않음 | 원 발행처의 현재 판본·변경 이력 확인 |
| 대상·조건 불일치 | 이름은 같지만 모델·단위·지역·적용 조건이 다름 | 대상 식별과 조건을 명시해 다시 탐색 |
| 근거가 서로 충돌함 | 같은 대상·시점·조건에 양립하지 않는 주장 | 원문·변경 이력·독립 관측 대조 |
| 여러 결과가 한 원문의 복제임 | 같은 인용 계보·동일 내용·전재 관계 | 독립성 요구가 있는 주장에 다른 근원 확보 |
| 관측과 예측이 어긋남 | 실제 오류·환경 변화가 기존 설명과 안 맞음 | 새 예외·변경·다른 원인 탐색 또는 현장 관측 |
| 범위를 판단할 수 없음 | 접근 실패·부분 추출·출처 미상·질문 모호 | 미확인 범위를 남기고 접근 가능한 근거·사람의 정보 사용 |

평가기의 출력은 `SUFFICIENT / INSUFFICIENT / CONFLICTED / UNKNOWN`과 부족한 항목·
그 판정의 근거로 구성한다. 일부만 충족하면 `INSUFFICIENT` 아래 충족·미충족 항목을
함께 남긴다. `SUFFICIENT`는 명시한 과제·범위·시점에 대한 판정이며 세계 전체에 빠진
정보가 없다는 보증이 아니다. 읽지 않은 영역의 충분성을 자동 추정하지 않는다.

LLM 평가는 위 항목과 원문 구간을 대조하는 보조 판단으로 사용한다. 출처 없는 ‘확신 90%’,
검색 결과 개수, cosine similarity, bandit score를 충분성 확률로 바꾸지 않는다.
알려진 누락·충돌·정답 사례로 충분성 평가기의 과신과 과소판정을 따로 검사한다.[S1][S2]

## 3. 언제 무엇을 가져오는가

선택은 사용자의 요구·현재 근거·변화 사건·예산을 함께 본다. 이미 알고 있는 URL의
본문을 읽는 것, 새 출처를 발견하는 검색, 원문의 최신성 확인, 사람에게 묻는 것은 서로
다른 연산이다. 아래는 우선순위가 있는 제안이며 고정 모델·점수 임계값을 헌법으로 만들지 않는다.

| 현재 조건 | 선택할 연산 | 다음 판정 |
| --- | --- | --- |
| 사용자가 검색·검증을 명시함 | 요청 범위의 외부 검색 또는 원문 확인 | 실제 원문으로 요청을 충족했는가 |
| 최신 외부 상태가 핵심이고 현재 근거가 없거나 낡음 | 공식 원천·연결된 provider에서 현재 판본 확인 | 현재성·적용 조건을 충족했는가 |
| 알려진 로컬 원문이 있으나 아직 안 읽음 | `LOCAL_READ` | 해당 구간이 빠진 항목을 채우는가 |
| 원문 URL은 알지만 본문·관련 구간이 없음 | `FETCH_SOURCE` | 본문을 실제로 읽었는가; snippet만 있는가 |
| 로컬 탐색으로 필수 근거를 얻지 못했고 외부 근거가 필요함 | `SEARCH_EXTERNAL` | 새 후보의 관련성·독립성·충분성 |
| 상충 주장 또는 실행 실패가 발생함 | 원천 재확인·반대 근거·대안 원인 탐색 | 충돌이 해소됐는가; 여전히 무엇이 미확인인가 |
| 필요한 것이 사용자의 목적·선호·비공개 현장 관측임 | `ASK_HUMAN` 또는 해당 관측 요청 | 공개 검색으로 추측하지 않고 그 정보를 얻었는가 |
| 명시한 범위의 필수 근거가 충분하고 현재성도 충족함 | `USE_CURRENT` | 답·행동이 그 근거와 조건을 보존하는가 |
| 충분한 근거를 두고 추론·호출만 실패함 | 추론·코드·실행 경계 진단 | 무의미한 추가 검색으로 오류를 가리지 않는가 |
| 승인된 관심 대상의 변경 알림·사람의 정정이 도착함 | `REVALIDATE_SOURCE` 후 영향을 받는 관계만 재활성화 | 실제 변경·관련성·권위·유효 시각 |
| 예산·접근 한계로 필수 근거를 더 얻지 못함 | `DEFER` 또는 근거 있는 부분만 답하기 | 남은 불확실성과 중단 이유 명시 |

현재성 확인이 명백히 필요한 요청에는 의미 없는 로컬 검색 단계를 선행시키지 않는다.
변하지 않는 제공 문서의 문장 편집·번역처럼 외부 사실 추가가 필요 없는 일은 외부 검색을
자동으로 붙이지 않는다. 과제 도중 새로운 주장을 만들거나 새 의존성을 발견하면 그 지점에서
다시 충분성을 판정한다. 검색은 작업 시작 때 한 번만 하는 절차가 아니다.[S2][S3]

질의는 ‘결론을 입증할 문장’보다 ‘어떤 대상의 어떤 조건이 빠졌는가’로 만든다. 임시 답변의
불확실한 고유명사·숫자를 확정 전제로 검색어에 넣지 않는다. 공식 원천·대안 표현·상충
근거를 과제에 맞게 선택한다. 연결된 적절한 provider가 있으면 그 조회 기능을 우선 사용한다.[S3][S4]

## 4. 검색을 언제 끝내는가

1. 필수 항목의 근거·현재성·조건이 충족되고, 답에 영향을 주는 충돌이 해결됐으면 사용한다.
2. 부족함이 남으면 다음 연산이 어느 항목을 해결할지 명시한다. 같은 질의·같은 복제 출처만
   반복되고 새 근거가 없으면 질의·원천·관측 방식을 바꾸거나 중단한다.
3. 호출·시간·바이트·비용 예산이 끝나면 `DEFER` 또는 범위를 줄인 답으로 끝낸다.
   예산 소진·검색 실패·접근 불가는 ‘사실이 존재하지 않음’이나 ‘검색이 충분함’의 증거가 아니다.
4. 보조 정보의 추가 획득은 예상되는 결정 개선과 비용·지연을 비교한다. 그 예상이 학습·
   보정되지 않았다면 정성적 설계 판단으로 표시한다. 보편적인 ‘3회 검색’·‘0.8 이상’ 기준은 없다.
5. 자율 구독·재탐색에는 관심 주제, 목적, 만료, 호출 한도, 취소 상태를 둔다. 사용자가 정한
   범위와 연결된 기능 안에서 자동 처리하며 모든 사용자에게 상시 수집을 기본값으로 두지 않는다.

최초 근거 항목 자체의 누락은 별도 문제다. 중요한 결정에서는 누락되기 쉬운 예외·대안
설명·원천 변경을 추가 탐색 후보로 둔다. 평가에서는 항목 목록에도 없던 필수 조건을 숨긴
사례를 사용해, 자신의 목록을 모두 채웠다는 이유만으로 잘못 종료하는지 검사한다.

## 5. 가져온 정보를 지속 상태에 연결한다

외부 획득 결과에는 자원 ID/URL, 발행 주체, 발행·수정·조회 시각(모르면 미상), 사건이
실제로 적용되는 시각, 판본/ETag/내용 hash, 사용한 구간, 관련 근거 항목, 출처 계보를 둔다.
검색 결과의 발견과 실제 본문 읽기를 구분한다. 원문·추출·요약·AI 해석은 각각의 출처와
변환을 갖는다. 가져온 페이지의 명령문은 자료로 취급하며 agent 지시·권한으로 승격하지 않는다.

```text
질문 / 사람의 정정 / 원천 변경 사건
→ 필요한 근거와 현재 상태의 부족함 판정
→ 로컬 읽기 / 외부 검색 / 원천 재확인 / 사람에게 묻기 / 보류
→ 원문·판본·시각·구간·계보 결속
→ 충돌·충분성 재판정 → 선택한 근거로 의미 실행
→ 실제 결과·사람의 평가 → 기존 owner 학습 경로 → 다음 선택
```

HTTP 캐시는 RFC 9111의 freshness·validation 계약을 따른다. 원천이 지원하면 ETag 등의
validator로 재확인하고 `304 Not Modified`에서는 기존 표현을 재사용한다. `304`는 그
표현의 재사용 근거이며 주장의 사실성·현재 과제 충분성을 보증하지 않는다. HTTP의 캐시
유효기간과 도메인 사실의 유효 시각도 다르다. 캐시할 수 없는 자료는 해당 저장 제한을 지킨다.[S5]

원문이 바뀌면 해당 판본을 사용한 요약·주장·규칙·예정 행동에 재검토 필요를 전달한다.
역사적 진술은 당시 판본과 시점으로 유지하고, 현재 행동이 소비할 판본만 다시 선택한다.
모든 변경을 모든 문맥에 즉시 주입하지 않는다. 일시 장애는 권위 하락·반증과 구별하며,
삭제·철회 이후 원문 접근과 파생 정보의 재사용은 출처의 권리·owner 계약에 따라 처리한다.

## 6. 인터넷 native하게 인류와 함께 움직인다는 뜻

사람은 자료 제공자뿐 아니라 목표를 제시하고, 일을 함께 수행하고, 설명을 정정하고,
결과의 유용성을 판단하는 참여자다. HSWM은 문서·서비스·사람·사건의 안정적인 식별과
변경 이력 위에서 작동한다. 서로 다른 관점은 작성자·조건·시점을 유지하며 연결한다.
게시물이 많이 복제됐다는 이유로 합의나 독립 검증으로 세지 않는다.

| 연결 방식 | 작동 방식 | 보존할 것 |
| --- | --- | --- |
| 필요한 때 발견·읽기 | 검색·공식 API·원문 fetch로 부족한 근거 확보 | 요청 목적·실제로 읽은 구간·조회 결과 |
| 변화에 반응 | 연결된 feed/webhook/WebSub가 변경을 알리면 해당 의존성 재검토 | 발행자·topic·사건 ID·중복·순서·cursor·만료 |
| 사람이 참여·정정 | 주장·반박·수정·작업 결과를 대상·역할에 연결 | 누가 어떤 자격·범위에서 무엇을 말했는가 |
| 공동 작업 결과 반환 | 근거·차이·미확인을 포함한 설명·작업물을 적절한 참여자에게 반환 | 대상 채널·발신 주체·공개 범위·전송 결과 |
| 경험으로 다음 사용 개선 | 획득·선택·실행 결과를 기존 W 학습 연결로 소비 | 관측/평가 구분·정책 판본·실제 다음 사용 |

WebSub는 publisher–hub–subscriber 사이의 변경 배포·구독 확인·유한 lease를 제공한다.
2026-06-02 Recommendation을 확인했다. 지원 원천에는 변경 알림을 사용할 수 있고,
미지원 원천에는 승인된 범위의 조건부 조회를 사용할 수 있다.[S6]
알림의 중복·역순·누락 가능성을 고려해 원천 revision을 다시 확인하고, 끊긴 구간은 저장된
cursor와 제한된 재조회로 메운다. 특정 protocol을 전 세계 참여의 필수 조건으로 강제하지 않는다.

ActivityPub의 actor·object·inbox/outbox·Update/Delete 전달은 분산 참여 어댑터의 참고다.
수신한 활동은 그 발행 주체의 활동이며 자동으로 사실·합의·HSWM 명령이 되지 않는다.
사용자의 직접 정정도 사용자 의도에 관한 결정인지 외부 세계에 관한 주장인지 구분한다.[S7]

공동 작업은 승인된 채널·상대·목적 안에서 수행한다. 이미 허용된 범위는 반복 확인하지 않는다.
새 외부 게시·제삼자 메시지·비공개 정보 공개는 그 행위의 명시적 지시가 있어야 한다.
이 문서를 작성하는 것으로 구독·외부 계정·게시 기능을 가동하지 않는다. 사람의 선호나
미관측 현장 정보만 필요한 경우에는 해당 사람에게 좁게 묻고 독립 작업은 계속한다.

## 7. 기존 HSWM에 구현할 위치와 현재 수준

| 경계 | 현재 재사용할 경로 | 추가 구현·연결할 것 |
| --- | --- | --- |
| 보유 근거 탐색 | `hswm-workspace navigate/follow/read`, source binding | 과제별 필수 항목과 구간 지지 판정 |
| 국소 의미 판단 | `prepareSemanticContext`, 역할 있는 semantic 실행 | 충분성·누락·충돌의 근거 있는 구조화 출력 |
| 다음 획득 선택 | 기존 activation policy·`executeActivationTraversal` | 읽기/검색/재확인/사람 질문의 후보와 실행 어댑터 |
| 외부 관측 유입 | 기존 tool/LLM I/O·outcome 결속 경계 | provider별 fetch 결과, HTTP 시각·validator·본문 추출 |
| 변화의 국소 전달 | 기존 UID·revision·의존 관계 | 구독/사건 cursor, 원천 변경에 따른 선택적 재검토 |
| 결과와 학습 | `executeActivationLoop`의 evaluator·owner admission·readback | 실제 검색의 누락 감소·오답·비용·유용성 피드백 연결 |
| 사람과 결과 교환 | 기존 역할·owner·참여 경계 | 채널별 수신·정정·허용된 반환, 중복 전송 방지 |

새로운 영속 엔진이나 별도 전역 W를 만들지 않는다. 위 판정은 기존 semantic 관계의 역할과
프로그램으로 표현하고 I/O adapter를 연결하는 방향이다. 이 문서의 표는 현재 API가 검색
충분성을 이미 자동 판정하거나 인터넷을 상시 구독한다는 의미가 아니다.

처음 연결할 범위는 ‘한 과제 → 근거 항목 → 실제 부족함 → 한 원천 획득 → 원문 검증 →
재판정 → 기존 의미 실행’으로 잡는다. 이어서 원천 변경·사람의 정정으로 해당 관계만
다시 활성화되는 경로를 연결한다. 자연어 분해·평가기·획득 정책의 효능은 각각 평가한다.
일반 사용에서 연결된 TRAIN 피드백·W 갱신은 기존 runtime이 자동 처리한다. 검색 횟수·
본문 저장·사용자의 단순 반응 수를 성공 보상으로 쓰지 않고, 원래 부족함이 해소되어 실제
결정·실행에 도움이 됐는지를 본다. 평가 미상·AUDIT·정당한 no-op은 그대로 유지한다.

## 8. 판정기와 통합을 확인할 사례

| 사례 | 기대 동작 |
| --- | --- |
| 관련 자료는 많지만 필수 예외 한 줄이 없음 | 불충분; 그 예외를 찾아 읽음 |
| 근거가 충분한데 모델이 계산을 틀림 | 추론/계산 진단; 무조건 재검색하지 않음 |
| 여러 뉴스가 같은 발표를 전재 | 하나의 출처 계보로 계산 |
| 공식 문서 판본과 설치 판본이 다름 | 판본을 맞춘 뒤 판단 |
| 오래된 캐시로 최신 상황 질문 | 원천 재확인; `304`여도 사실의 적용 시각 별도 판정 |
| 같은 조건의 두 원문이 충돌 | 충돌 상태 유지; 변경 이력·독립 근거 대조 |
| 첫 검색 뒤 새로 필요한 대상이 드러남 | 부족한 관계를 따라 후속 질의 생성 |
| 사용자만 아는 선택 기준이 빠짐 | 그 기준을 질문; 공개 검색으로 추측하지 않음 |
| 원천이 삭제되거나 접근이 끊김 | 미확인/접근 제한; 부재·반증으로 단정하지 않음 |
| 변경 알림 중복·역순·구독 만료 | 중복 적용 방지·판본 재확인·만료 상태 보존 |
| 외부 페이지가 실행 명령을 지시함 | 자료 내용으로 유지; 권한·agent 지시로 승격하지 않음 |
| 사람이 결과를 정정하고 후속 작업을 수행함 | 작성자·수정 대상·실제 사용 결과를 연결 |
| 처음 만든 근거 목록에도 없는 중요한 예외 | 충분성 평가기의 오판으로 드러내고 목록·정책 재검토 |
| 검색 비용이 늘지만 결정을 바꾸지 못함 | 한계 이득 평가·질의 변경 또는 중단 |

동일 과제·모델·예산에서 무검색, 고정 1회, 항상 검색, 적응 획득을 비교한다. 잘못된 충분
판정, 불필요 검색, 필수 조건 누락, 인용 지지, 현재성 위반, 답변 품질·보류율·비용·지연을
함께 측정한다. 답한 것만의 정확도와 전체 과제 중 답한 비율을 함께 보고, 어려운 질문을
모두 보류해 정확도만 높이는 방식도 드러낸다. 검색 평가기가 사용한 정보를 정답으로
재활용하지 않고, 미관측 과제·원천 변경·사람 정정의 후속 사용을 포함한다.

이번 산출물은 사용자 방향·문헌 근거·구현 계약·내용 탐색 연결이다. 위 사례의 native 실행,
자동 검색 평가기의 성능, 인터넷 상시 참여의 통합 실험을 완료한 것은 아니다.

## 9. 확인한 원전과 적용 한계

확인일 2026-10-24. 다음 7종은 논문 또는 표준 원문이다. 논문 수치·모델 성과를 HSWM의
측정값으로 옮기지 않는다. 새로운 판단 기준과 구현 순서는 AI의 적용 해석이다.
