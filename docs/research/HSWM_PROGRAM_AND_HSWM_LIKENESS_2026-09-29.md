# HSWM 프로그램과 HSWM적인 성질의 구분

2026-09-29 · `agent:codex` · `SECONDARY_AI / PROPOSED`.
[사용자 원문](../canon/sources/USER_PRIMARY_HSWM_PROGRAM_ADJECTIVE_DISTINCTION_2026-09-29.txt)은
프로그램의 이름과 형용사적 성질을 분리하라는 직접 지시다. 영어 명칭은 질문·후보 제시이며,
사용자가 `HSWMLY` 또는 아래 권장 표기를 확정했다고 기록하지 않는다.

| 구분 | 권장 표기 | 의미 |
| --- | --- | --- |
| 프로그램·시스템 이름 | **HSWM** / **the HSWM system** | 특정 소프트웨어 시스템과 그 정체성·실행·학습 계약 |
| 형용사 | **HSWM-like** | 데이터·프로그램·구조 등의 구성 방식이 HSWM적이라는 성질 |
| 성질을 가리키는 명사 | **HSWM-likeness** | 그 성질 자체 또는 명시한 프로파일에 따른 충족 정도 |
| 방식을 나타내는 표현 | **in an HSWM-like manner** | HSWM적인 방식으로 처리하거나 조직함 |

위 영어 표현은 AI의 명명 권고이며 별도의 사용자 ratification이 아니다.
`HSWM-like data`, `an HSWM-like program`, `the HSWM-likeness of this dataset`처럼 쓴다.
`HSWMLY`는 프로젝트 조어·브랜드로 사용할 수 있지만 품사와 의미가 바로 드러나지는 않는다.
`-ly`는 부사를 만들 때 흔히 쓰이며 형용사를 만드는 용법도 있으므로 문법적으로 무조건
불가능하다고 말하지 않는다. 명확한 기술 문서 표기는 `HSWM-like`를 권한다.
단어 하나를 새로 만들고 싶을 때 `HSWMic`도 가능한 조어 후보지만 표준 영어 용어는 아니다.
영어 근거: [Cambridge의 부사 형태 설명](https://dictionary.cambridge.org/grammar/british-grammar/adverbs-forms),
[-ly의 형용사·부사 용법](https://dictionary.cambridge.org/us/dictionary/english/ly).
명명 권고는 이 문법 자료를 바탕으로 한 판단이며 사전이 HSWM 파생어를 등재했다는 뜻이 아니다.

## 대상과 성질

**HSWM적이다**의 일반적인 대상은 데이터, 프로그램, 시스템, 규칙, 지식 구조다.
이 성질은 의미·역할·문맥을 보존하는 관계 구조, 여러 해상도의 지도와 원천 내용의 결속,
분산된 국소 접근·활성화 가능성, 원천과 구분된 위치·연결·전이 성향의 조정 가능성으로
설명한다. 데이터의 원천은 문서뿐 아니라 관측·레코드·프로그램 객체일 수 있다.

데이터는 스스로 실행되거나 LLM을 포함하지 않아도 이런 구성을 가질 수 있다. 활성화되는
정도는 그 데이터를 읽는 프로그램·정책·작업 문맥에도 의존한다. 따라서 저장 구조의 성질과
실제 실행에서 관측한 성질을 분리한다. 프로그램은 자신이 유지·해석하는 구조와 활성화·갱신
행동을 대상으로 평가한다. 실제 HSWM 프로그램의 정체성은 기존 헌법을 이어받는다.

| 문장 | 온톨로지에서의 판별 |
| --- | --- |
| 이것은 HSWM 프로그램이다 | 특정 시스템의 정체성·구현에 관한 주장 |
| 이 데이터는 HSWM적이다 | 데이터 구성에 대한 성질 주장 |
| 이 다른 프로그램은 HSWM적이다 | 별도 프로그램의 구조·동작에 대한 성질 주장 |
| HSWM이 생성·저장한 데이터다 | 생성/저장 provenance; HSWM적이라는 판정과 별개 |
| HSWM과 호환된다 | 인터페이스 호환성; HSWM적이라는 판정과 별개 |

`HSWM-like(x)`는 `x is HSWM`이나 `x was generated by HSWM`을 함의하지 않는다.
HSWM 밖에서 구축한 데이터도 HSWM적일 수 있고, HSWM이 저장한 항목이라는 이유만으로
그 항목에 해당 성질이 자동 부여되지는 않는다. CHU는 이 프로그램과 데이터의 위치·관계를
포괄하는 더 넓은 개념으로 유지한다.

## 온톨로지와 점수의 범위 수정

`HSWM`은 시스템 정체성의 대상, `HSWM-likeness`는 여러 종류의 대상에 적용할 수 있는
구성 성질로 분리한다. 둘을 `sameAs`나 프로그램의 subclass 관계로 연결하지 않는다.
성질 판정은 `subject UID/revision`, `subject kind`, `profile version`, `context/workload`,
`evidence`, `assessment`를 가진 attribution 가능한 기록으로 둔다. 단순한 boolean 하나로
실제 효능까지 확정하지 않는다.

앞서 만든 [규칙 평가 v1](HSWM_LIKE_RULE_ONTOLOGY_AND_EVALUATION_2026-09-29.md)은
이 일반 성질의 **규칙 분야 평가 프로파일**이다. 전체 HSWM-likeness의 유일 정의가 아니다.
규칙 점수의 필수 원문 읽기·예외 조건을 임의의 모든 데이터에 그대로 강제하지 않는다.
데이터 평가는 source/representation/role/context/local access의 구조를 먼저 다루고,
실행 평가는 reader/interpreter와 workload에서 activation·비용·결과를 별도로 다룬다.
새 일반 점수나 데이터 점수의 가중치를 여기서 발명하지 않는다. 서로 다른 프로파일의 점수는
같은 척도라고 가정하지 않는다.

이 구분을 별도 KG 개념으로 기록하고 기존 규칙 개념에는 적용 범위 정정을 추가한다.
원문과 hash가 결속된 이전 보고서·ontology·게시 snapshot은 당시 버전으로 보존한다.
이 문서는 기존 HSWM 프로그램의 런타임·헌법·학습 의미를 새로 바꾸지 않는다.
