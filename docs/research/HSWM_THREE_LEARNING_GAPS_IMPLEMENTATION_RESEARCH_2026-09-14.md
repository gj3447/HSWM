## 1. 관계 의미는 관측·실행·개입과 묶어서 배운다

첫 구현에서는 현재 선언된 특징만 재조합하는 한계를 명시하고, 실패가 모이는 조건에서
**새 변수 후보와 그 값을 얻는 방법**을 함께 제안하게 한다. 후보에는 원본 관측,
추출기 revision, 값의 domain·단위, 관측 시점, 결측 의미, 적용 조건을 둔다.
관측할 수 없는 변수라면 새 측정을 요청하는 후보로 남긴다. 이름이나 embedding을
만들었다는 이유로 그 원인이 발견됐다고 기록하지 않는다.

반복되는 실행 프로그램에서는 재사용 가능한 관계·부분 프로그램을 추출할 수 있다.
DreamCoder와 Stitch는 이 부분의 참고 방법이다. 다만 기본 언어와 과제·프로그램 집합이
주어진 상태의 library learning이므로, 압축률 개선은 세계의 인과 의미가 맞다는 증거가
아니다. HSWM에서는 확장한 프로그램의 동작 보존과 새 사례의 결과 예측을 따로 검사한다.
[DreamCoder, PLDI 2021](https://doi.org/10.1145/3453483.3454080),
[Stitch, 저자 논문](https://mlb2251.github.io/stitch.pdf)

2026년 *Beyond identifiability*는 적은 개입 환경과 유한 표본으로 잠재 인과 표현을
복원하는 결과를 제시한다. 그러나 선형 decoder·선형 DAG SEM, 독립 noise,
strongly-separating 개입 설계, 두 noise-scale 설정 등 강한 가정이 있다.
그래프는 label permutation, 표현은 scale/permutation까지의 식별이다.
일반 LLM 텍스트에 바로 적용하는 알고리즘으로 채택하지 않고, 가정이 성립하는 수치
세계에서만 비교 후보로 둔다. [원문 v1, §2–3](https://arxiv.org/html/2603.25796v1)

실행 가능한 첫 형태는 다음과 같다. 서로 다른 관계 후보들이 다른 결과를 예측하는
상황을 찾고, 허용된 관측·개입을 선택한다. 결과를 본 뒤 예측이 틀린 후보의 적용 범위를
좁히거나 새 조건을 제안한다. 실험 선택을 위한 탐색 자료와 최종 평가 자료를 분리하며,
모든 후보 생성·실패 비용도 비교 예산에 포함한다. 이 절차는 HSWM에 대한 구현 제안이다.

**G1 수용 조건:** 초기 활성 프로그램에 없는 변수 추출기/조건부 관계를 경험에서
제안하고, 후보 생성에 사용하지 않은 개입·조건에서 예측을 검증한다. 단순한 이름 교체,
메모리 검색, 같은 DSL의 더 긴 경로와 구별해서 보고한다. 같은 관측·행동·예산을 받는
강한 text/program learner와 비교한다. 정보가 부족한 조건은 `UNKNOWN`으로 남긴다.
비교 기준인 초기 프로그램, 후보 생성기·프롬프트 revision, 허용 read-set, 기본 연산
목록을 사전에 고정한다. extractor나 정답이 프롬프트·benchmark metadata·generator에
숨겨진 경우를 검사한다. LLM 사전학습 지식 전체의 부재까지 입증하는 것은 아니므로
새로움의 범위는 공개한 초기 구성과 실험 과제로 한정한다.

## 2. 좋은 점수 속의 틀린 관계도 찾아서 고친다

예측 오차는 조사할 관계를 고르는 신호다. 그것만으로 인과 기여가 계산되지는 않는다.
관계 revision별 사전 예측, 실제로 읽은 근거, 행동, 지연된 실제 결과를 먼저 연결한다.
최종 보상과 독립적으로 확인 가능한 결과를 별도 필드로 보존한다.

InT는 정답 풀이를 참고해 실패한 추론의 첫 오류를 찾고 한 단계를 바꾼 뒤 학습한다.
참고 풀이를 제거한 ablation은 그 정보의 중요성을 보여준다. HSWM에는 오류 위치와
수정 후보 생성 방식이 유용하지만, 논문의 중심은 실패 trace이며 **좋은 보상을 받은
trace 속 모든 잘못된 관계의 발견**을 해결한 결과는 아니다. 학습용 정답에 접근한
후보를 독립 held-out 성과로 계산해서도 안 된다.
[InT, 2026-01, §3–4](https://arxiv.org/html/2601.14209v1)

C3는 같은 관측 문맥에서 대안 행동을 만들고, 고정한 후속 정책 분포에서 여러 번
이어 실행해 결과를 비교한다. 문맥별 leave-one-out baseline으로 행동의 기여를
추정한다. 이는 전체 점수를 모든 관계에 똑같이 나누는 방식의 대안이다. HSWM에
옮길 때는 문맥 복원 가능성, 대안의 지지 범위, 후속 정책과 평가기 버전을 명시해야
한다. 고정 문맥에서도 후속 실행은 확률적일 수 있다.
[C3, 2026-03, §2–3](https://arxiv.org/html/2603.06859v1)

두 종류의 주장을 구분한다. 특정 과거 사건의 **같은 개체 반사실**에는 noise 복원 등
추가적인 구조 가정이 필요하다. 반면 앞으로의 사례를 무작위로 배정해 비교하는
**평균 개입 효과**는 모든 숨은 상태를 byte 단위로 재현해야만 추정할 수 있는 것은
아니다. 배정·일관성·간섭 처리·표본 대상과 고정된 분석이 필요하다. replay가 없다는
이유만으로 모든 인과 연구를 막거나, seed가 같다는 이유로 완전한 반사실을 주장하지
않는다. [DoWhy v0.13의 반사실 가정](https://www.pywhy.org/dowhy/v0.13/user_guide/causal_tasks/what_if/counterfactuals.html)

**G2 수용 조건:** 보상은 높지만 잘못된 관계를 포함하는 사례에서 원본·교정·제거·복원·
의미를 바꾸지 않는 sham을 비교한다. 분량·표현 등 사전에 무관하다고 정한 보상 지름길도
흔든다. 교정이 실제 결과에 미친 효과를 구간과 함께 보고하고, 올바른 인접 관계는
보존한다. 교정된 관계가 기존 canonical 전이 경로를 통해 다음 새 사례의 행동까지
바꿔야 한다. 효과가 불분명하면 미식별/불확정이지 기여 0이나 성공이 아니다.
관계가 틀렸다는 판정의 출처도 R-00에서 고정한다. 합성 세계의 숨긴 ground truth 또는
명시적인 독립 판정 근거를 사용하고, 후보 생성자·결과 평가자별 접근 범위를 기록한다.
그 근거가 확정되지 않은 실제 세계 사례는 잘못된 관계의 교정이 아닌 경쟁 가설
검증으로 분류한다. 학습 때 제공한 관계 정답을 최종 검증 정답처럼 재사용하지 않는다.

## 3. 합성은 예외·불확실성·학습의 귀속까지 보존한다

셀의 출력은 답과 confidence 숫자 하나로 축약하지 않는다. 조건별 적용 범위, 알려진
반례, 예측 분포 또는 오차 정보, calibration 자료/시기, 공유 근거·의존 관계,
하위 revision 계보를 상위에서 참조할 수 있어야 한다. 하위 둘이 같은 틀린 근거를
쓰는 경우를 독립된 두 증거로 계산하지 않는다. 공동 성공 확률을 하위 confidence의
곱으로 계산하려면 해당 독립 가정이 실제로 성립해야 한다.

*Bucketing the Good Apples*는 주어진 추상화가 잘 맞는 입력 집합과 남는 집합을
개입 관계로 나눠 보는 방법을 제시한다. 후보 추상화와 과제 해석이 먼저 필요하며,
탐색은 heuristic이다. 이를 참고해 **설명되지 않은 예외 집합을 삭제하지 않고 다음
변수·관계 발견의 입력으로 유지**한다. 원 논문의 정답 입력 필터를 전체 성능 평가의
분모 축소로 사용하지 않는다. [2026-05 원문, Algorithms 1–2](https://arxiv.org/html/2605.02234v1)

추상화와 개입의 일치성도 제한된 가정 아래 검사해야 한다. 2021년 compositional
abstraction error 연구는 유한 개입 모델의 변환 오차를 합성하는 틀을,
2026년 Lorenz–Tull은 구성 요소 수준까지 강화한 추상화를 제안한다. 둘 다 적응하는
HSWM 전체의 학습 보존을 자동으로 증명하지 않는다.
[UAI 2021](https://proceedings.mlr.press/v161/rischel21a.html),
[Lorenz–Tull, 2026-02, 초록 확인](https://arxiv.org/abs/2602.16612v1)

특히 비선형 대응 함수를 무제한으로 허용하면 무작위 네트워크도 원하는 알고리즘과
맞아 보이게 만드는 반례가 있다. 따라서 대응 함수의 종류·복잡도와 학습 자료를
고정하고, 새 입력/개입 및 random/untrained control로 검사한다. 대응 함수가 대신
추론하는 현상을 HSWM의 의미 학습으로 세지 않는다.
[Sutter 외, NeurIPS 2025, v2](https://arxiv.org/html/2507.08802v2)

불확실성은 조건별로 측정한다. ICML 2025 CPCL은 continual learning의 calibration을
다루지만 그 보장은 가정에 의존하며 asymptotic 결과다. 임의 분포 변화·재귀 합성에서
유한 표본 coverage가 자동 보존된다는 근거로 쓰지 않는다. 보정 범위를 벗어나면 기존
확률을 그대로 재사용하지 않고 새 보정 자료와 변화 이력을 남긴다.
[CPCL, ICML 2025, 초록 확인](https://proceedings.mlr.press/v267/gao25i.html)

**G3 수용 조건:** 같은 첫-scale 구성을 두 scale로 합성해 하위 예외, 공유 원인으로
생기는 동시 실패, 새 분포, 부정적 전이를 시험한다. 실제·균등·shuffled credit를
비교하고, 전체 결과가 필요한 하위 관계를 바꾸는지 검증한다. 새 과제의 평균만으로
기존 조건의 손상을 숨기지 않는다. 첫-scale의 유효한 지지가 R-05 효과 실험의
선행 조건이며, RED가 이 조건을 만족시키지는 않는다.
별도로 동일 하위 셀의 계산·정보·총예산·조정자 용량을 유지한 비합성 대조군을 둔다.
credit ablation과 이 비교를 구별해 추가 문맥이나 계산량의 이득을 합성 효과로 세지 않는다.

| P2 변수·관계 후보 | `relation-program-research.ts`의 현 DSL 한계를 보존하며 별도 제안 함수가 추출기·조건·실행 의미·반례를 반환한다. 검사된 후보만 기존 schema에 매핑하는 수정 후보가 된다. | R-01, R-02; G1 |
| P3 관계별 교정과 실제 전이 | 동일 문맥 replay 또는 전향적 무작위 배정 port, outcome evaluator, 효과·불확실성의 순수 계산. 기존 `canonical-atom-v2-state-journal.ts` 및 admission 경계와 연결해 outcome→credit→revision→새 행동을 완성한다. | R-01, R-02, R-03; G2 |
| P4 합성 계약과 정리 연결 | 적용 조건·반례·공유 근거·불확실성·revision 계보를 보존하는 순수 합성 함수. 선언한 개입 변환과 오류 한계, 실제 관측을 Lean 전제에 연결한다. 이 설계/반례 준비는 첫-scale 결과 전에도 할 수 있다. | R-04; G3의 준비 |
| P5 같은 구성의 두-scale 효과 | 첫-scale 지지가 확보된 뒤 동일 후보의 두-scale에서 개입, 실제/균등/shuffled credit, 유지·전이·공동 실패를 측정한다. | R-05; G3의 실증 |

Effect service는 관측·모델 호출·평가·저장의 I/O를 맡고, 후보 생성 규칙·오차 계산·
조건 합성·수정 결정은 순수 immutable domain 함수로 둔다. 자동 학습을 영구히 금지하는
설계가 아니다. 자격이 확인된 결과가 **기존 typed·소유권·출처 경계 안에서 실제 수정으로
이어지게 하는 것**이 목표다. 실험용 receipt를 더 쌓는 것만으로 완료 처리하지 않는다.

P1/R-00의 고정 계약 해시를 모든 후보·배정·평가·수정 기록이 참조하도록 한다.
탐색 도중 estimand나 기준을 바꾸면 새 탐색 계약으로 남기며, 변경 전 계약의 최종
판정에 몰래 합치지 않는다. 이는 연구의 의미 보존 조건이며 새 사용자 승인 절차가 아니다.

Lean의 다음 대상도 같은 구성이어야 한다. 사전 예측과 결과의 순서, 조건·예외 보존,
명시적인 개입/오차 가정 아래 합성 경계를 증명한다. 학습 향상을 전제로 받은 뒤 향상을
결론으로 꺼내는 정리를 새 효능 증명으로 세지 않는다. 현재 정리와 TS 실행 사이의
refinement와 실험 가정의 충족은 별도 근거가 필요하다.

## 도구 선택과 연구 판정

우선 기존 TS/Effect, source-bound KG, SHACL/SPARQL, Lean, 평가·실행 기록 경계를
재사용한다. DoWhy는 식별·추정·반증 방법을 확인하는 외부 분석 참고이며 HSWM core를
Python으로 되돌리는 의존성이 아니다. DreamCoder/Stitch와 논문별 코드는 방법 후보다.
이번 조사에서 패키지·모델·repository를 설치하거나 실행하지 않았다. 향후 특정 구현을
채택할 때 공식/저자 출처, 정확한 commit/version·digest·license와 격리 검증을 결속한다.
논문이나 코드 공개를 표준·적합성 인증으로 부르지 않는다.

구체적인 testbed 참고로는 2026년 5월 CausaLab이 가깝다. 관측→개입→관계 가설 수정과
새 사례 예측을 평가하며, 최종 예측 점수와 그래프 복원을 따로 측정한다. 다만 변수
목록과 함수 계열은 주어지고, 개입도 incoming cause를 끊는 hard-do가 아닌 shift 방식이다.
따라서 그대로 쓰면 새 변수 발견 G1 전체를 평가할 수 없다. 논문이 연결한 코드 URL은
확인 시 404여서 즉시 설치할 도구로 추천하지 않는다. 기존 HSWM 측정 환경에 이 평가
구분을 적용하는 것이 먼저다. [CausaLab v2, 2026-05-28](https://arxiv.org/html/2605.26029v2)

P1에서 선택할 과제는 관계 교정의 실제 결과를 독립 측정하고 허용된 개입을 할 수 있어야
한다. 저자가 정의한 합성 세계는 측정 도구의 첫 자격 확인에는 유용하지만, 그 성공을
일반 의미 발견으로 확대하지 않는다. 비공개/새 사례, 같은 정보의 강한 learner,
NO_UPDATE·SHAM·SHUFFLED·REMOVE/RESTORE 비교는 기존 연구 계약대로 유지한다.
후보 탐색 뒤 최종 검증을 분리하고 다중 비교·순차 선택을 분석에 반영한다.

실패는 정확한 방법·과제·표본·가정에 결속해 보존한다. 기준을 낮추거나 실패를 이름만
바꾸거나 더 큰 scale로 옮겨 성공처럼 만들지 않는다. 효과 크기와 표본 수는 아직
선택하지 않았으며 이 문서로 어떤 간극도 `SOLVED`가 되지 않는다.

조사는 HF paper discovery와 원 논문·학회·공식 문서를 이용한 범위 한정 검색이다.
각 소스의 실제 읽은 범위는 JSON에 기록했다. 전수 문헌 검토나 도구 보급률 조사는
아니며, 2026년 preprint를 확립된 표준이나 HSWM 실증 근거로 승격하지 않는다.
